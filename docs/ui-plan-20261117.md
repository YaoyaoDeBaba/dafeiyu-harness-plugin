# selfloop UI 施工计划（16 条待办的排期与做法）

> 来源：`docs/ui-todo-20261117.md`（16 条）。原则：**先修"错"，再做"顺"，最后做"美"**。
> 批次之间可独立发版；每批都要带判据（不许只靠肉眼）。

## 批次 A｜修正「显示的语义」（1、3、4、12）

| 待办 | 做法 | 判据 |
|---|---|---|
| ① 肥鱼自治→肥鱼接单 | 改 tab 名/面板标题/所有文案 | 全仓 grep 不到「肥鱼自治」 |
| ③ 顶部显示 Agent 在干嘛 | 节点 id → 人话动词表（阶段1 一套、阶段2 一套、含子代理名） | 每个节点都有映射，缺一条测试红 |
| ④ 标题精炼 + 下拉收窄 | `/start` 存 `title`（需求首句 ≤12 字，可编辑）；`/state.orders[]` 返回 title；下拉只显示 title，菜单宽度 ≤ 面板宽度 | 新单标题不是 `sl-xxx-2026...`；菜单不溢出 |
| ⑫ 状态置顶 + 指示灯 | 状态 = {phase, text, agents:[{name, task}]}；「等待子代理返回」一格内列在跑的子代理 | 跑单时有 ≥1 个子代理时，状态里能看到它的名字与任务 |

## 批次 B｜修正「交互会打断人」（6、7、14、16）

| 待办 | 做法 | 判据 |
|---|---|---|
| ⑥ 跑单中点胶囊＝开面板 | 有订单且未结束 → 打开/聚焦面板；只有「无订单」或「已结束」才进下单模式 | 跑单时点胶囊不出现下单浮层 |
| ⑦ 提交后不停住 | 面板显示「已提交，等 Agent 继续」；后端写 `ui-done-request.json`；主 Agent/后台 job 见到就跑 `done` | 提交后 30s 内状态从「等你」变为下一站 |
| ⑭ 意图确认走表单 | 后端加 `POST /confirm`（任意阶段可追加问题）；主 Agent 不再在聊天里问取舍 | 本轮取色那种取舍出现在面板里 |
| ⑯ 输入框不被刷新清空 | 重绘前存 value/selection 回填；输入时静默 2s 不重绘；输入区移出重绘范围 | 连打 10 秒不丢字（自动化：脚本模拟 input 后强制 refresh） |

## 批次 C｜信息组织（5、8、9、10、11）

做法统一：面板按**轮次分组**，每组三块可折叠区（需求 / 意向确认 / 吐槽记录 / 调查与转译）。
- **当前轮默认展开**，历史轮默认折叠但可展开（⑧⑨⑩⑪）。
- 需求原文常驻在「状态」下方（⑧），默认折叠。
- 数据侧：`/state` 需要按轮返回 `rounds[{round, requirement, confirm:{questions,answers}, interrupts, research, translate, plan}]`。

判据：新开一单 → 当前轮 4 块都在且展开；跑完一轮 → 上一轮自动折叠，点开能看。

## 批次 D｜流程保证（15）

吐槽多消费点：
- `2.5-decide` 交活时，把未消费的 jsonl 条目并入 `decide.gapsForNextRound`；
- `3.1-summarize` 时列出「你说过但没处理的」；
- `2.5` 的 check 强制：jsonl 有条目但 decide 里没出现 → 不放行；
- 去重按语义（前 8 字 + 相似度），不要只按 `at+text`。

判据：写一条吐槽 → 走完 decide → 它出现在 `decide.gapsForNextRound` 里。

## 批次 E｜视觉（13）

- 卡片体系：状态卡（蓝）、告警卡（黄）、失败卡（红）、完成卡（绿）、中性卡（灰）；
- emoji 前缀：📋 需求 / 🎯 判据 / 🔍 调查 / 🛠 执行 / ⚡ 电弧 / ☁ 云 / 💬 吐槽 / ✅ 通过 / ❌ 未过；
- 字号与颜色分层：标题 13px 600、正文 12.5px、元信息 11px #8a8f98；
- 判据：面板内所有区块都有分类色 + 图标；不再出现「整屏灰白」。

## 建议顺序与工作量

1. **B 批**（交互会打断人，最影响体验）：1~1.5 天
2. **A 批**（语义与状态）：0.5~1 天
3. **C 批**（信息组织，要改 `/state` 结构）：1~1.5 天
4. **D 批**（流程保证）：0.5 天
5. **E 批**（视觉）：1 天

合计约 4.5~5.5 天。每批独立发版 + 重启，不攒大版本。

## 一个前置决定（要你拍）

**面板数据要不要一次性重构成「按轮分组」**？
- 选**是**：C 批一次性做对，但 `/state` 要大改，前面 A/B 批的字段会动两次；
- 选**否**：A/B 批先用现有字段快速修，C 批再重构（改动重复，但每批都能马上用）。

我倾向**否**（先让你用顺，再重构）。
