# 闭环引擎 · 适配层说明（adapter.json 契约）

> P1 引入。一句话：**脚本不再知道"这是哪个项目"，所有现场信息都在 adapter.json 里。**
> 换项目 = 换/改一份 adapter，执行器不用动。执行器确实要改的时候：改动写进仓库根的 `CHANGELOG.md`，并把改动点同步回上游原件（案例 A，见 README「案例与来源」；两边已经分叉，别整文件覆盖）。

## 一、四个问题 + 字段表

`adapter.json` 只回答四件事：**怎么改配置 / 哪张页面 / 怎么冻到某时刻 / 怎么起服务与浏览器**。

| 字段 | 类型 | 一句话说明 |
|---|---|---|
| `schema` | string | 契约版本号，当前 `closed-loop-adapter/3`（写给未来的校验器看） |
| `template` | bool | `true` = 这份只是**字段模板**，没有可跑的目标/白名单；`iter.ps1` 不带 `-Adapter` 时直接拒绝运行 |
| `name` | string | 适配层名字，只用于日志与证据包里的身份标记 |
| `clientRoot` | string | **client 根目录**（镜像或本体）：vfx.json 在这里、静态服也以它为根 |
| `config.path` | string | 配置文件在 `clientRoot` 下的**相对路径**，如 `resource/lab/vfx/vfx.json` |
| `config.block` | string | 要调的参数块**全路径**，如 `effects.FireRay.fireBeamG1M1`（`effects.` 前缀可省） |
| `page.file` | string | 冻帧页面在 `clientRoot` 下的**相对路径**，如 `_dev/probe.html`（页面本身由你的宿主提供） |
| `page.query` | string | 页面 query 模板，支持 `{seed}` `{timeMs}` `{tier}` 占位符 |
| `page.readyExpr` | string | 判定"页面就绪"的 JS 表达式（返回 `"true"` 才算就绪）；不写走中性默认 `document.readyState === "complete"`，并打一条 warn |
| `freeze.protocol` | string | 冻帧协议名。两种：`noloop-step`（无循环 + 定步长推进）/ `url-time`（见 §5）；换协议 = 改 iter.ps1 那一段 |
| `freeze.stepMs` | int | 单步推进的毫秒数（等价 `window.step(N, stepMs)` 的第二参） |
| `freeze.targetTimeMs` | int | 目标冻结时刻（ms）；实际步数 = round(target/stepMs)，全 run 不变 |
| `freeze.seed` | int | 相位种子，写进 page.query 的 `{seed}`，全 run 不变 |
| `render.tier` | string | 画质档 `low/medium/high/ultra`（`ultra` 表示不打补丁） |
| `render.width` / `render.height` | int | 视口尺寸（同时决定 `--window-size` 与 CDP 设备度量覆盖） |
| `server.staticPort` | int | 静态服端口，**必填**（没有默认值） |
| `server.cdpPort` | int | 浏览器 CDP 端口，**必填**（没有默认值） |
| `server.browserProfilePrefix` | string | 浏览器 profile 目录前缀，**必填**（没有默认值）；全名 = 前缀 + run 目录名 |
| `server.staticScript` | string | 静态服脚本路径；留空则用 `<Root>\_tmp_static.js`；相对路径按脚本目录解析 |
| `server.bind` | string | 静态服绑定地址，默认 `127.0.0.1` |
| `browser.exe` | string | 浏览器可执行文件；留空则按 `exeCandidates` 顺序找第一个存在的 |
| `browser.exeCandidates` | string[] | 候选浏览器路径（Edge x86 / Edge / Chrome） |
| `browser.args` | string[] | 浏览器 flag 模板，支持 `{width}` `{height}` `{cdpPort}` `{profile}` 占位符 |
| `metrics` | string[] | 本 adapter 的指标向量声明（自检用：不在 metrics.js 产出集合里的会 warn） |
| `tools.metricsJs` | string | 指标脚本路径（只读复用的 E1 metrics.js） |
| `tools.capture` | string | 浏览器/截图边界脚本，默认 `capture.mjs`（相对脚本目录） |
| `guard.bodyClient` | string | 本体 client 路径：只用来交"本体前后哈希"，**从不写**；非空时自动并入 `guard.protectPaths` |
| `guard.protectPaths` | string[] | **写入禁区**：改参脚本拒绝把任何文件写进这些目录（含子目录）。可缺、可空数组；缺了只 warn，证据包记 `guardEnforced:false`——注意这等于**本轮没有任何本体写保护**（applier 只保证 `out≠base`），不是"弱保护" |
| `retarget.note` | string | 纯注释：告诉接手的人换项目改哪儿 |

**命中优先级**：显式命令行参数 > adapter > **报错**。
没有"内置兜底"这一层了：目标帧（`-Target` / `target`）、白名单（`-Params` / `params`）两处都没有就报错，报错文案会把该补什么写出来。端口 / 档位这类给命令行是覆盖，不给就用 adapter 里的。

### 1.1 写入禁区 `guard.protectPaths`

挡的是"改参时写回本体"这件事。语义（与 `iter.ps1` / `writeguard.js` 同一口径）：

| 项 | 口径 |
|---|---|
| 类型 | `string[]`，可缺、可空数组（独立试验宿主确实没有本体可保护） |
| 元素 | 绝对路径 / 相对路径 / `%ENV%` 模板；**相对路径按 adapter 所在目录**展开（与 `clientRoot` / `target.path` 同口径） |
| 模板展开失败 | **硬错**，不降级成 warn（声明了却执行不了，比不声明更危险） |
| 匹配 | **subtree**：等于它、或在它下面；按路径段边界比（`...\a\b` 不匹配 `...\a\bc`） |
| 大小写 | Windows 忽略，其他平台区分 |
| 分隔符 | 比较前归一、剥尾部分隔符；out 的父目录存在时按 realpath 比（`_镜像` 可能是指向本体的 junction） |
| 与 `bodyClient` | `bodyClient` 非空就自动并入（并集），老 adapter 一个字不改也有保护；两个都写不冲突，不用重复写 |
| 强制点 | ① `iter.ps1` 启动时查一次镜像配置路径（早失败，不浪费预算）② `apply.js` / `apply_params.js` 每次写前查（`--protect` 传进去） |
| 直接手调 | `node apply.js ...` / `node apply_params.js ...` 的护栏不再是隐式的，拒写得自己加 `--protect <目录>` |
| 拒写时 | 退出码 3 + 一行中文（含 out、命中的那条 protectPath、"改 clientRoot / -Mirror"的提示） |

## 二、用法

```powershell
# 1) 三输入就够：一份 adapter + 预算 + 输出目录（目标/白名单都在 adapter 的 target / params 节里）
pwsh -File <包目录>\harness\iter.ps1 -Adapter <adapter.json> -Budget 20 -Out runs\r1

# 2) 换项目 / 换分辨率 / 换画质：换 adapter 就行，命令形状不变
pwsh -File <包目录>\harness\iter.ps1 -Adapter <另一份 adapter.json> -Budget 20 -Out runs\r2

# 3) 临时覆盖目标 / 白名单，显式给端口/档位/镜像：命令行优先级最高
pwsh -File <包目录>\harness\iter.ps1 -Adapter <adapter.json> -Target '{"widthPx":32}' -Params widthPx,distM `
     -W 640 -H 360 -Tier low -StaticPort 8243 -CdpPort 9425 -Budget 20 -Out runs\r3
```

不传 `-Adapter` 会读包内的 `harness/adapter.json`——那份是**字段模板**（`template:true`），`iter.ps1` 会直接拒绝运行。要跑就指定 `domains/vfx-render/adapters/` 下的示例，或照 `examples/minimal.json` 写一份自己的。

`-Params` 里的 `widthPx,distM` 只是 vfx 领域那份示例的参数名，不是引擎内置的：别的领域按自己 adapter 的 `params.list` 写。

## 三、浏览器/截图边界（为 Playwright 铺路）

- 领域语义（改哪份配置、播哪个特效、冻到第几毫秒、画质补丁、回读校验）→ 留在 `iter.ps1`。
  > v2 补充：`metrics` / `score` 两节（见 §四）把"量什么、怎么加权"也从脚本里搬了出来；`freeze.clock`
  > 可选 `wall`（默认，页面按墙上时间走）/ `virtual`（推进前把 `performance.now` 换成虚拟钟，消掉
  > 帧级抖动 —— 火柱走 M2 直通层，uTime 是墙上时间，不冻就做不到"同 seed 两次逐字节相同"）。
- 浏览器语义（起进程、连 CDP、导航、等 ready、求值、截图、进程收尾）→ 全在 `capture.mjs`。
- `capture.ps1` 只是 NDJSON 管道（PowerShell ↔ Node）。

**下一步替换点：只动 `capture.mjs` 内部实现**，协议（`start/goto/eval/waitfor/shot/viewport/stop`）不变，
`iter.ps1` 与 `capture.ps1` 都不用改。Playwright 的映射关系写在 `capture.mjs` 头注释里。

## 四、v2 新增两节：`metrics` 与 `score`（P2.5）

一句话：**代码里备一套通用提取器（`metrics2.js`），配置只做「选哪个 / 传什么参数 / 怎么归一化 / 权重多少 / 什么情况下罚分」。**
adapter 不再只是"现场信息"，它同时是**测量口径**。换特效要动的就是这两节 + 四个现场字段。

### 4.1 `metrics[]`：每项一个槽位

| 字段 | 必填 | 一句话 |
|---|---|---|
| `id` | ✓ | 产出的键名；score 认这个。同一个 `extract` 可以用不同 opts 起两个 id（如 `cov` 与 `covCore`） |
| `extract` | ✓ | 提取器名，见 §4.3。未知名字直接报错（不静默兜底） |
| `opts` | | 该提取器自己的参数，省略 = 提取器默认值 |
| `norm` | | 归一化：`{mode:"range",range:[lo,hi]}` / `{mode:"pctrel",floor:f}` / `{mode:"abs",scale:s}` / `{mode:"identity"}`；可选 `clamp:true`。**直方图类指标**（`hueHist`）的 `norm` 作用在「环形 L1 距离」上（目标值当 0），不是 `\|m−t\|`；`pctrel` 对直方图没意义 |
| `weight` | | 权重（默认 1）。距离 = Σ(w·nd)/Σw，所以权重和为 1 不是硬要求 |
| `enabled` | | `false` = 这个槽位暂时下线（不用删配置） |

### 4.2 `score`：距离形式 + 惩罚

```json
"score": {
  "type": "l1",
  "penalties": [
    { "id": "coreGone", "when": "ratioCore <= 0 || covCore < 0.5 * T.covCore", "add": 0.5 }
  ]
}
```

- `type`：本版只实现 `l1`（加权 L1 平均 + 惩罚）。
- `when`：**极小的比较式，不走 eval/Function**。只认 `<key> <op> <数>` / `<key> <op> <数>*T.<key>` / `<key> <op> T.<key>`，
  `<op>` ∈ `< <= > >= ==`，多个条件用 `||`。`key` 先查该行顶层，再查 `diag`；`T.<key>` = 目标帧同名量。
  也可写成对象 `{anyOf:[...]}` / `{allOf:[...]}`。**任何 key 缺失都会直接报错**（静默不命中的惩罚是坑）。
- `add`：命中一次加多少（`coreGone` 沿用火柱的 0.5 = "核心塌陷"闸门）。

### 4.3 提取器清单（`metrics2.js` 的 `EXTRACTORS`，12 个）

| `extract` | 输出 | 参数（默认） | 一句话 |
|---|---|---|---|
| `mean` | 0~255 | — | 平均亮度（Rec709 luma） |
| `p160` | 0~1 | `thr:160` | 高光面积：luma>thr 的像素占比 |
| `lapVar` | 0~万 | `luma:40` | 细节能量：Laplacian 方差（只在 luma>luma 的内点上算） |
| `warmFrac` | 0~1 | `luma:80,rMin:140,rg:1.15,gb:0.9` | 暖色占比：亮像素里 `r>rMin && r>g*rg && g>=b*gb` 的比例 |
| `coldFrac` | 0~1 | `luma:20,delta:8` | 冷色占比：全图 `luma>luma && b>r+delta` 的比例 |
| `hueHist` | **数组**（18 个桶，和=1） | `luma:40,minSat:0.15` | 色相直方图：HSB 的 H 投进 18 个 20° 等宽桶，权重 = 饱和度×亮度；灰/黑/白（低饱和）不计入 |
| `hueMean` | 0~360 | `luma:40,minSat:0.15` | 色相**圆均值**（同权重），给人看报告用的标量；无彩色像素 → 0 |
| `cov` | 0~1 | `luma:40` | 亮区面积：luma>luma 的像素占比 |
| `maskIoU` | 0~1 | `luma:40`，**需要参考帧** | 亮区掩码重叠率（`iter.ps1` 用 `--ref 目标帧` 传进来） |
| `bbox` | px / 比值 | `luma:40,field:w\|h\|area\|aspect\|fill` | 亮区包围盒取一个数 |
| `stepRatio` | 0~1 | `minBinPct:0.0005,dropRatio:0.1` | **阶跃边占比**（0.11.0）：256 桶 luma 直方图里「断崖」数 / 非空 bin 数；越高越像硬切档，连续渐变 = 0 |
| `speckleFrac` | 0~1 | `speckleDelta:24` | **孤立点占比**（0.11.0）：像素与其 8 邻域 luma 中位数之差 > delta 的比例；越高越像噪点 |

> 所有提取器都额外吃一个 `opts.mask`（见 §4.3.2）。**不写它 = 全图，与升级前完全一致。**

`hueHist` 是**唯一一个输出数组的提取器**（直方图进不了 `|m−t|` 那种比较）：

- 比较口径：`score.js` 认出数组后不算 `|m−t|`，而是算 **环形 L1**（见 §4.3.1），再把**现成的 `norm`** 作用在这个距离上（目标值当 0）。
- 18 桶时距离单位是"桶"、上限 9（半圈），所以 `{"mode":"abs","scale":9}` 或 `{"mode":"range","range":[0,9]}` 就把它压到 0~1，权重语义与标量指标一模一样。
- `pctrel` 对直方图没有意义（它拿 `|t|` 做分母，直方图没有单个目标值），配了会**直接报错**，不会静默除出 Infinity。
- 没人给 opts 时 `luma:40, minSat:0.15`；`minSat` 是饱和度硬下限，**权重 = sat×val** 是软下限（灰/白/黑的 sat=0 ⇒ 权重 0）。
- 退化语义：整张无彩色 → 18 个 0 的空直方图（不是 NaN、不炸）；两张都空 → 距离 0；只有一边空 → 满距离 9（不假装"差不多"）。

### 4.3.1 环形 L1（`hueHist` 的距离，`metrics2.js` 的 `circularL1`）

色相是环形量（0° 与 340° 是邻居）。朴素 `Σ|a_i−b_i|` 在这上面是错的：350° 与 10° 会被算成"跨了 17 个桶"，而 350° 与 180° 也是 2 桶——死区就是这么来的。

```
把候选的质量沿色相环搬到目标上，搬过 1 个桶记 1（末桶与首桶相邻）
d = min   Σ_{j=1..n-1} | Σ_{i<cut+j} (a_i − b_i) |
   cut
```

即"在哪个桶切开圆环"里取最省的一种（直方图 L1 运输距离的环形版本，O(n²)，18 桶可忽略）。实例：`350°→10° = 1`、`350°→180° = 8`、`红(0°)→蓝(210°) = 8`、`红→红 = 0`。

> 别把它写成"整条直方图按最优位移对齐"——那个版本会把任意两张**单峰**直方图的距离都对齐到 0（红 vs 蓝也变 0），等于把色相判据废掉。

外加一块 **`diag`（只读诊断，不进距离，score 一行都不读）**：`mean/p160/cov40/lapVar40/warmFrac/coldFrac/hueMean/covCore/ratioCore/bboxW/bboxH/maskIoU`，
既能给人看，也是历史字段（`iter.ps1`/`finalize.js` 打印用）的兼容垫。**`diag` 永远是全图口径**（不跟 `opts.mask` 走）——改它会打破老证据包的可比性。

### 4.3.2 掩膜 `opts.mask`（0.11.0）：先在主体上算，再谈数字

两条实验暴露的是**分母**问题：火焰只占画面 3.8~6.4%，全帧统计把主体稀释掉；换题材/换占屏比还会冒出假趋势（实测过一次 `p=0.0034` 的假相关）。所以提取器统一支持在掩膜内统计：

```json
"metrics": [
  { "id": "cov", "extract": "cov", "opts": { "mask": { "mode": "content", "luma": 40, "dilate": 1, "minAreaPct": 0.2 } } }
]
```

| 字段 | 默认 | 一句话 |
|---|---|---|
| `mode` | `content` | `content` = 按 `luma >= luma` 圈前景 → 取**最大连通域**（8 邻域）→ 可选膨胀；`none` = 显式全图 |
| `luma` | 40 | 圈区域用的亮度门限（`>=`：含边界那圈） |
| `dilate` | 1 | 方形膨胀半径（像素），把主体外沿半透明的一圈纳进来 |
| `minAreaPct` | 0.2 | **百分数**（0.2 = 0.2%）。掩膜面积低于它就退回全图 |

- 所有统计（`cov` / `lapVar` / `warmFrac` / `hueHist` / `bbox` …）的分母换成**掩膜内像素数**；`stepRatio` / `speckleFrac` 也只算掩膜内。
- **回退不许静默**：面积 < `minAreaPct` 时照常给数（全图口径），但 `extractOne` 会在该图的返回对象上写 `maskFallback: true`，并给 `maskInfo`（`mode/luma/dilate/minAreaPct/areaPct/largestPct`）。看到这个标记就必须在报告里写"这次量的是整帧"。
- **向后兼容**：不写 `opts.mask` → 与升级前逐字节一致（`npm test` 的 162 条钉的就是这个契约）。
- 已知边界：`content` 只按亮度圈区域，**分不出"亮主体"与"亮背景"**。主体不亮、或背景比主体还亮时，掩膜会圈到背景上，指标会"稳定地量错东西"——比没有掩膜更危险。自查办法：「掩膜内 vs 全帧」的同一指标必须有明显差（几乎相等 = 掩膜≈全图），且 `areaPct` 要和主体实际占屏比一个量级；最硬的证据是把主体裁出来单独量一次，掩膜内的值应落在它的量级上。

### 4.3.3 正对照纪律（0.11.0）：新指标先在"已知变坏"的图上翻得动

上一代的 posterize 类量对**肉眼可见**的硬切档只有噪声级反应（其中"3×3 极差 <8"那版是零响应——门限把噪点/台阶边自己的像素排除掉了）。教训写成了测试：

- `test/metrics.test.mjs` 用代码生成合成图（**不联网**）：`smooth` / `banded4` / `speckled` / `small_subject` / `subject_only` / `tiny_subject`。
- 断言即判据：`stepRatio(banded4) > 3×stepRatio(smooth)`、`speckleFrac(speckled) > 3×speckleFrac(smooth)`、5% 主体下掩膜内 `lapVar` 比全帧高一个数量级且回到主体纯图的量级、面积不够时 `maskFallback:true` 且不崩、不写 mask 与 `mode:"none"` 同值。
- **纪律测试**：`EXTRACTORS_WITH_POSITIVE_CONTROL` 里每加一个名字，文件里就得有一条真在标定它的断言；往 `EXTRACTORS` 里塞一个没进清单的提取器 → `checkLedger` 直接报「新增提取器没正对照」。以后谁加指标不带标定，测试会拦住他。
- 弄坏能红（两条都在文件里、随时可复跑）：`SELFLOOP_METRICS_MUTANT=stepAlwaysCliff`（断崖判据放宽到永真 → 剁档对照红）、`SELFLOOP_METRICS_MUTANT=legacy3x3Speckle`（换回老的 3×3 门限 → 噪点对照红）。

### 4.4 两个只差配置的实例

## 五、v3：目标帧 / 冻帧协议 / 白名单（P2.6）

> 一句话：**跑一轮只剩三个输入 —— 一份 adapter + 预算 + 输出目录。**
> `iter.ps1 -Adapter <path> -Budget 20 -Out <dir>`，不再需要 `-Target` / `-Params`。

### 5.1 新增三节（`target` / `params` 必须有个来源，其余可选）

| 字段 | 类型 | 一句话 |
|---|---|---|
| `config.format` | string | 配置形态：`vfx-block`（默认，`effects.<E>.<B>`，走 `apply.js`）/ `flat-params`（扁平 `{params:{...}}`，走 `apply_params.js`） |
| `target.mode` | string | 目标帧怎么来：`png` / `params` / `default` |
| `target.path` | string | `mode=png` 时给帧路径（相对 adapter 目录或绝对） |
| `target.params` | object | `mode=params` 时给 `{参数: 数值}`，跑起来渲一张当目标 |
| `params.mode` | string | 白名单怎么来：`list` / `activity` / `auto`（未实现，只留接口 + 明确报错） |
| `params.list` | string[] | `mode=list`：参数名或 `name=初值` |
| `params.activityPath` | string | `mode=activity`：活性扫描表路径（如 `<你的工作目录>\active_params.json`） |
| `params.state` | string | 只挑这个 state 的参数，默认 `live` |
| `params.limit` | int | 最多挑几个，默认 6 |
| `params.requireInBlock` | bool | 默认 `true`：跳过"不在本块内"的路由层旋钮（W11 的 preset/flowMul 那些） |
| `params.skip` | string[] | 显式拉黑的名字 |
| `freeze.protocol` | string | 现在两种：`noloop-step`（页面暴露推进接口）/ `url-time`（页面按 `?time=<秒>` 自冻） |
| `freeze.clock` | string | `wall` / `virtual`（noloop-step）/ `n/a`（url-time） |
| `freeze.urlTemplate` | string | `url-time` 专用，必须含 `{sec}` 或 `{timeSec}`；缺省退回 `page.file + page.query` |
| `freeze.verify` | string | `url-time` 冻帧自检：`strict`（默认，同 URL 连拍两张必须逐字节相同，否则报错）/ `warn` / `off` |
| `page.readbackExpr` | string | 回读校验用哪句 JS（证明参数真被吃到）。不给 = **跳过回读自检** + 打一条 warn，证据包里记 `selfCheck:false`；给了就按它回读，缺参数直接报错 |
| `tools.apply` | string | 改参脚本（缺省按 `config.format` 选 `apply.js` / `apply_params.js`） |

### 5.2 优先级（三条都不许静默兜底）

```
目标帧：  命令行 -Target  >  adapter.target  >  报错
白名单：  命令行 -Params  >  adapter.params  >  报错
冻帧协议：adapter.freeze.protocol（只有两种），协议用错宿主 -> 报错
```

三条是同一个口径：**没有内置兜底值**。目标帧 / 白名单两处都没给就硬错——不会拿某个项目的两个参数名顶上。

### 5.3 两种协议的内部抽象

`iter.ps1` 里只有一个动作：**跳到某时刻并截图**。

| 协议 | 怎么做 | 自检 |
|---|---|---|
| `noloop-step` | 改参 → 重载 → 打画质档 → `playFx` → 注入虚拟钟 → `window.step(n,ms)` | 宿主必须有 `window.step` / `window.playFx`，否则报错 |
| `url-time` | 改参 → 重载到 `...?time=<秒>`（**没有推进过程**，步长与 clock 都是 0/n-a） | 同一 URL 连拍两张逐字节比，不同就报错 |

### 5.4 实例

| 文件 | 目标 | 白名单 | 协议 |
|---|---|---|---|
| `adapters\fire-ray.json` | `params` `{widthPx:30,distM:8}` | `list` `[widthPx,distM]` | `noloop-step` + `virtual` |
| `adapters\fire-ray-png.json` | `png`（指向 `runs\p25-fire-1\shots\target.png`） | 同上 | 同上（反证：换目标模式只改配置） |
| `adapters\fire-ray-activity.json` | 同上 | `activity`（`<你的工作目录>\active_params.json`，limit 3） | 同上 |
| `adapters\fire-ray-urltime.json` | 同上 | 同上 | `url-time`（宿主不支持 → 明确报错） |
| `adapters\demo-url-time.json` | `default`（不 patch + `?time=0.9`） | `list` `[bristle=2.2,flow=1.6]` | `url-time` + `verify:strict` |
| `adapters\demo-noloopstep.json` | 同上 | 同上 | `noloop-step`（宿主不支持 → 明确报错） |

## 六、`observe` 节：观测是一条命令的输出（0.4.0）

> 前面五节讲的都是**截图链路**：改配置 → 起浏览器 → 冻帧 → 截图 → 量像素。
> 这一节补另一条：观测 = **跑一条命令、从 stdout 取数**。它证明的不是"渲染类目标可调"，而是"任何可测目标可调"。
>
> **缺 `observe` 节 = 老 adapter，行为完全不变。** 这一节是纯增量，包里三份 vfx 示例与用户手上的旧配置一个字都不用改。

### 6.1 两个执行器并列，不是父子

| | 截图链路 | 命令链路 |
|---|---|---|
| 入口 | `harness/iter.ps1` | `harness/cmdloop.mjs` |
| 平台 | Windows 专用（PowerShell + Edge） | 纯 node，跨平台 |
| 观测 | 浏览器页面 → 截图 → `metrics2.js` | 一条命令 → stdout → `observe.parse` |
| 判据 | `score.js` | **同一份** `score.js`（`require` 进来，没有第二套距离） |
| 搜索 | 活性预检 + 坐标下降（PowerShell） | 活性预检 + 坐标下降（node，语义照抄，见 `skills/selfloop/references/command-observe.md` §4） |
| 证据包 | `curve.csv` / `best.json` / `report.md` / `shots/` | 同三件命名同构 + `outputs/`（原始命令输出，截断 4KB）+ `params/` |

`iter.ps1` 的主流程**一行没动**：命令观测是新入口，不是它的分支。动了它，浏览器闭环那套实测过的进程卫生/冻帧自检就得重验一遍，不划算。

### 6.2 字段表

```json
"observe": {
  "type": "command",
  "cmd": "node ./probe.mjs",        // {params} 占位；相对路径按 adapter 目录展开；不走 shell
  "cwd": "",                        // 可选，默认 adapter 目录
  "timeoutMs": 30000,
  "parse": "json",                  // json | number | line:k=v
  "stability": { "repeat": 3, "maxSpread": 0.02 },  // 可选，但**不写也生效**（默认就是这一档）
  "metrics": [ { "id": "loss", "field": "loss", "norm": {"mode":"abs","scale":1}, "weight": 1 } ]
}
```

| 字段 | 类型 | 一句话说明 |
|---|---|---|
| `observe.type` | string | 必须 `command`；其他值硬错（本版只实现这一种）。缺整节 = 截图链路 |
| `observe.cmd` | string | 要跑的命令。自带极小分词器（空白 + `'` `"`），**不走 shell**；相对路径按 adapter 目录展开；可含 `{params}` |
| `observe.cwd` | string | 工作目录，默认 adapter 所在目录 |
| `observe.timeoutMs` | int | 单次超时，默认 30000；超了**中文硬错**（不当 0） |
| `observe.parse` | string | `json`（一个 JSON 对象）/ `number`（整个 stdout 是一个数，只能配 1 条指标）/ `line:k=v`（每行 `key=数值`） |
| `observe.stability` | object | 稳定性闸（0.4.1）：`{repeat: 3, maxSpread: 0.02}`。**不写也生效**；`repeat: 1` = 显式关掉并 warn |
| `observe.metrics[]` | array | `{id, field, weight, norm}`：`id` 是证据包列名（也是距离用的键），`field` 是输出里的字段名（缺省 = `id`，可写 `a.b` 走嵌套） |
| `target.mode` | string | 命令观测认 `params`（用目标参数跑一次命令取指标）/ `metrics`（直接给 `{指标: 数值}`，不跑命令）；`png` 对本链路没有意义 |
| `config.format` | string | 命令观测恒为 `flat-params`（`vfx-block` 要靠浏览器读，会硬错） |
| `params.mode` | string | 只支持 `list`（`activity` / `auto` 是渲染那边指向活性表的，命令链路没有） |

**稳定性闸（`observe.stability`，0.4.1）**：截图链路的等价物是 `freeze.verify=strict`（同 URL 连拍两张逐字节比）——
命令链路在**搜索之前**（起点已评估、活性预检之前）用起点参数把命令连跑 `repeat` 次，对每条指标算
`spread = (max-min)/max(|mean|,1e-9)`；任一 `spread > maxSpread` → **中文硬错**（点名指标 / spread / 阈值 / 原始值），
不降级、不自动取平均。起点那一次算第 1 次采样，所以默认只多花 `repeat-1 = 2` 次评估，**记进预算**；
预算不够也硬错（提示提高 `--budget` 或显式 `repeat: 1`）。非法值（`repeat < 1` 或非整数、`maxSpread ∉ (0,1]`）同样是中文硬错。
`best.json` 里落 `stability: {repeat, maxSpread, ok, spreads, values, checked, spend}`，`report.md` 里有一张逐次采样的小表。
细节与"怎么造不稳定 demo 自测"见 `skills/selfloop/references/command-observe.md` §6。

**参数怎么交给命令（写死，只有这一种）**：每次评估写 `<run>/params/eNNN.json`，然后
① `cmd` 里的 `{params}` 占位替换成它的绝对路径；② 环境变量 `SELFLOOP_PARAMS` 指向同一个文件。
**它绝不写 adapter 目录 / clientRoot**——参数文件只落 run 目录。

### 6.3 失败全部硬错（不许静默当 0）

| 情况 | 表现 |
|---|---|
| 命令超时 | `[命令观测] 命令超时（>30000ms）：...`，退出码 1 |
| 命令非零退出 | `[命令观测] 命令非零退出（exit=7）：...`，退出码 1 |
| 输出解析不出来 | `[命令观测] observe.parse=json 但 stdout 不是合法 JSON: ...（前 200 字：...）` |
| 指标缺失 | `[命令观测] 指标缺失：输出里取不到数字字段 size（metric size）—— 不许当 0 静默通过` |
| 命令起不来 | `[命令观测] 命令起不来：...（argv=[...]）：ENOENT ...` |
| 观测不稳定（0.4.1） | `[命令观测] 观测不稳定：指标 \`loss\` 的相对离散度 0.100000 超过上限 maxSpread=0.02（repeat=3 次的原始值：1、1.05、0.95）` |

只有一种"不算变化"：命令跑成功、数也取到了、但**距离没动** → 该参数判 `dead`（活性扫描剔除），这是正常结论，不是错误。

### 6.4 证据包

`curve.csv` / `best.json` / `report.md` 的字段与命名和截图链路**同构**（`round` / `eval_seq` / `id` / `note` / 参数列 / `dist` / `pen` / `m:<指标>` / `nd:<指标>`），末尾那一列从 `png` 换成 `output`（`outputs/` 里的相对路径）。

额外两样：
- `outputs/`：每次评估的原始命令输出（stdout / stderr / argv / 指标 / 距离），**单份截断到 4096 字节**，超了标 `truncated:true`；
- `params/`：每次评估交给命令的参数文件（复核"这轮到底吃了什么"）。

`best.json` 另有 `stability: {repeat, maxSpread, ok, spreads, values, checked, spend}`，`report.md` 里对应"观测稳定性闸"一节（逐次采样 + spread + 判定）；
`evaluations` 多一个 `stability` 计数（那几次评估的原始输出同样落在 `outputs/` 里）。指纹里只放闸的**配置**，不放采样数值。

`best.json.hash` 口径照抄 `finalize.js`：只放决定"搜到哪"的东西（判据配置 / 命令 / 种子与步长 / 白名单 / 基线 sha / 每点参数与距离 / 终止原因），**不放**时间、路径、原始输出 → 换 `--out` 目录同 seed 重跑，hash 必须一致。

### 6.5 怎么跑

```bash
node harness/cmdloop.mjs --adapter examples/command-echo.json --out runs/cmd1 --budget 40
```

选项：`--budget` / `--seed` / `--step-ratio` / `--max-rounds` / `--max-stagnant` / `--strategy coordinate|random` / `--params a,b=3`。
默认值与 `iter.ps1` 同量级（步长 0.1、maxRounds 20、maxStagnant 2），只有 `--budget` 默认从 60 降到 30（命令通常比一帧渲染便宜，但慢命令要看 `--budget` 自己调）。
注意预算里还要留出**稳定性闸**那 2 次（0.4.1 默认 `repeat: 3`）：`目标 1 + 起点 1 + 闸 2` 是最小可用预算，再小会硬错而不是"偷偷少跑"。
