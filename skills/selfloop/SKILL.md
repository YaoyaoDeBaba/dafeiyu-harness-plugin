# Selfloop（权臣）· 通用闭环引擎

## 0. 你是谁（先分流，越界就是事故）
- **主 Agent**（2.1~2.5）：跨轮闭环归你——活性扫描 / 选轴 / 搜索 / 判定 / 要不要下一轮。
- **执行员**（子代理，2.2）：做**有限**本地自迭代，最多自调 `maxSelfIterations`（默认 3）；三条停止条件满足任一即停——①硬判据全在带内；②用满轮次预算；③平台期：连续 2 轮**无显著提升**（主判据改善 <5%，或交付帧平均像素差 <2%）。
- 停下必须**如实交**：当前值 + 差多少 + 卡在哪个约束（禁止「已优化」这种空话）；每轮自迭代留一行 `rounds/r<N>/iters.md`；细则与自检清单见 `references/executor-brief.md`。
## 1. 开工三步（照做，别跳）
```bash
node harness/preflight.mjs --run <run目录> --ref <参考图或帧目录>   # ① 建骨架+量参考，并列出还差什么
# ② 派调查员（≥2 条带 URL 的 findings、≥1 条 opensource/paper、used 写 usedFor）→ ③ 填 intent 并 confirmed
```
**preflight 没过就改代码 = 跳过流程**（判据：`extracted[]` 非空 + `confirmed`）；两次受控实验都栽在这。
## 这是什么

给定「想要的样子」——一张目标图，或一组目标数值——自动找出最接近的参数组合，**几十秒到几分钟**出结果，并留下可复验的证据包。

引擎对题材没有偏好：它只要求**三件事能配出来**（下面三个概念）。渲染特效是今天接上的第一个领域（`domains/vfx-render/`），换成别的目标只是在 adapter 里换实现，引擎本身不动。

它只解决**形**：粗细、长度、节奏、面积、亮度这类能算的量；不解决**色 / 质 / 味**，也不替人判断成品好不好看。

## 三个概念（引擎与题材的分界）

- **观测**：任意能给出可比较数值的探针（渲染图、日志、接口响应、UI 状态）。
  合格的标准只有一条——**同一个输入跑两次，能给出可比的数**。不可复现的观测量不算观测，只是噪声。
- **判定**：可配置的判据与距离（不做裁判，只做粗筛与报警）；指标、权重、归一、罚项全写在 adapter 里。它能排序和报警，「好不好看」不能问它。
- **搜索**：可配置的参数空间（先扫活性，再选轴）；白名单在 adapter 的 `params` 节，可比条件在 `freeze` 节。**先扫活性再搜索**——见硬规则 ①。

## 开工前先确认三件事（缺一个就别开始）

1. 有能跑通的回路：**改配置 → 出观测 → 算判据**。插件版把执行器放在包内 `harness/`，现场位置由环境变量（如 `%VFX_LOOP_CLIENT%`）或命令行 `-Mirror` 给，包里不含任何本机路径。
   **环境**：Node ≥ 22.19；执行器是 Windows 专用（PowerShell + Edge），首装要浏览器 —— 用系统 Edge 零下载，走 Playwright 的 Chromium 约 740 MB（只要无头约 290 MB，`npx playwright install --only-shell chromium`）。
2. 有一个具体目标：**一张目标图**，或**一份 JSON 目标参数**（如 `{"widthPx":32,"distM":3.6}`）。
3. 有一个能写的输出目录（证据包落这里），且**不覆盖**别人的 run 目录。

## 五条硬规则（烧过钱换来的，不许绕过）

### ① 没做参数活性扫描，不许开始搜索

参数表 ≠ 生效参数。一个「看起来有几十个旋钮」的系统，实测可能只有几根真轴，其余改了输出**逐字节相同**。
（实测过一次：修路由前 2 根真轴 / 13 个死参数；修好后 12 根可搜索轴，其中 6 个复活、7 个确认无解。**这个数字会随管线变化，别抄，扫一遍就有**。）
不先扫描就搜索，代价是：预算花在死参数上、把「没接通」误判成「算法不行」、还可能让搜索学会作弊。
→ 扫描做法与五分法见 `references/workflow.md` 第 1 步。

### ② 对比必须锁「绝对毫秒 + seed」，不是锁「帧数」

可比的充要条件：**同一个 seed + 落到同一个绝对时刻 + 同档位 + 同分辨率**。
`step(16, 20ms)` 和 `step(20, 16ms)` 只要都落在 320ms，出图 SHA 可以完全相同；反过来，落到 340ms 和 320ms 就是两个世界——**同一版本不同时刻的差，常常比版本之间的差还大**。
所以报告里写的必须是「320ms」，不是「第 16 帧」。

### ③ 判据只认数字，图只用于给人看

截图的坑：异步、缓存、读错帧，都可能让你拿到一张**旧画面**。
- 判据 / 闸门 / 回归 → 只认数值（指标、哈希、像素统计、日志计数）
- 沟通 / 汇报 / 给人看 → 图
- 两者冲突 → **以数字为准**，再去查图为什么不对

### ④ 闸门新增断言必须验「故意弄坏能红」

断言只 `log()` 不 `exit 1`，闸门就形同虚设——外面很多范本就栽在这。
新增一条断言后，必须现场做一次反证：**造假数据 / 删图 / 写坏一行 → 必须 FAIL 且退出码非零**。验不过的断言等于没加。

### ⑤ 对抗样本（噪声 / 模糊）不得被判为更优

距离类指标对「糊」和「噪」不敏感，实测会**优选更糊更暗的那张**（机器盲评 0/4，人 4/4）。
所以每次出 best，都要再拿一批劣化样本（加噪、高斯模糊、降对比）去比：**只要有一个劣化样本的分数优于 best，就不许把这次结果交出去**，先修判据。

## 标准流程（每步的判据与失败含义在 references/workflow.md）

```text
1 活性扫描 → 2 选轴 → 3 搜索 → 4 证据包 → 5 半自动判定（换了管线 / 参数路由就重跑）
```

五步的产物：一张参数表（状态/管哪个指标/灵敏度）→ 一份白名单（2–3 根轴）→ 曲线 + 最优参数 → 六件套 → 一句人话结论。

## 跑一轮（命令 / 产物 / 报告要素）

三样输入：**adapter + 预算 + 输出目录**。换目标就换 adapter，命令形状不变；跑之前先过需求转译闸（没有 `intent.json` 会直接拒跑）。完整命令、一次 run 的产物清单、报告里必须写清的九项、两条执行器怎么选：**`references/run-recipes.md`**。


## 什么时候别用它

| 情况 | 为什么不行 |
|---|---|
| **想全自动交付** | 判据能自动调「形」，不能判断好坏。实测盲评机器 0/4、人 4/4；把「变细变暗」当成「更近」。必须人点头。 |
| **跨题材直接套** | 判据阈值是每个领域各自标定的。换题材要先重跑活性扫描，且阈值要重新标定。 |
| **要求美术级神似** | 距离只配做粗筛 / 报警。颜色、质感、笔触、光的层次它一概测不出来。 |
| **目标本身是错的** | 目标帧若是旧画面或错档位，闭环会非常认真地收敛到一个错的东西。先验目标。 |
