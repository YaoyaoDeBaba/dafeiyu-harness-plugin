# 读参考：GIF 拆帧、双通道识图、以及「模型读图 ≠ 结论」

> 什么时候读这篇：手上是 GIF/视频参考、需要判断"这张参考长什么样"、或者准备把参考图交给模型看。

## 1. preflight 只量 PNG

`preflight.mjs --ref <目录>` 只收 `*.png`（第 41 行），非 PNG 会被静默跳过。
所以 **GIF / 视频必须先拆帧**，把帧放进 `refs/frames/` 再量。

- **GIF**：大肥鱼接单界面的下单动作会用浏览器 `ImageDecoder` 逐帧解，导出 `refs/frames/<名>-gNNN.png`
  （上限 60 帧）；命令行侧也可以自己放帧。
- **视频**：这一期不支持，下一期补抽帧。
- 拆帧失败时 UI 会提示「GIF 未能拆帧，可能量不了」——看到这句就别指望判据了。

## 2. 双通道识图（免 key 网页 + API）

判断"参考像什么"时，优先用大肥鱼识图，两个通道**并行读、交叉比对**：

1. **豆包网页（免 key）**：设置页「肥鱼识图」→ 网页版 → 「登录 豆包」；宿主弹一次有头浏览器，
   cookie 落在 `<DSH_HOME>/storages/dsh-remote-dafeiyu/webvision/doubao/`，之后无头复用。
2. **API（mimo）**：同页配置；**读图用 `mimo-v2.6-pro`**（flash 在长会话里会串图/漏图）。
3. 宿主侧同源路由：`POST /api/dsh-remote-dafeiyu/vision/recognize`（还有 `/vision/models`、`/vision/web/status`）。

**一致性口径**：两个通道都读 → 一致项当证据；分歧项单独标出来，别取平均。

## 3. 模型读图只当线索

用户的文字描述**优先于**模型读图。2026-11-16 踩过：把一段 3D 挥砍参考读成「长弧能量刃 + 碎片」，
用户直接否掉。判据里的数字必须来自 `ref-probe` 量出来的实测区间，不能来自"模型说是这样"。

## 4. 参考不足时怎么问

参考只有一张静帧、而需求会动（云要翻滚、电弧要闪）时，别拿静帧硬凑动效判据：
要么补帧（GIF/视频），要么把动效判据降级成 `noMetric` 并写明理由，交给人判。
