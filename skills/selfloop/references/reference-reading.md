# 读参考：GIF 拆帧、以及「要识图时去哪儿」

> 什么时候读这篇：手上是 GIF 参考、需要判断"这张参考长什么样"、或者准备把参考图交给模型看。

## 1. preflight 只量 PNG

`preflight.mjs --ref <目录>` 只收 `*.png`，非 PNG 会被静默跳过。所以 **GIF / 视频必须先拆帧**，
把帧放进 `refs/frames/` 再量。

- **GIF**：selfloop 的下单界面会用浏览器 `ImageDecoder` 逐帧解，导出 `refs/frames/<名>-gNNN.png`
  （上限 60 帧）；命令行侧也可以自己往 `refs/frames/` 放帧。
- **视频**：这一期不支持，下一期补抽帧。
- 拆帧失败时界面会提示「GIF 未能拆帧，可能量不了」——看到这句就别指望量化判据了。

## 2. 要「看懂参考」时：用大肥鱼的识图能力

如果这一单需要判断"参考里是什么/长什么样"（而不是只量像素），**用大肥鱼插件的识图能力**——
它有网页免 key 与 API 两条通道，具体怎么配、怎么调、模型选哪个，**看识图工具自己的 skill**，
本文件不重复、也不替它规定用法。

这里只记一条纪律：**模型读图的结果只当线索，不当结论**。

## 3. 模型读图 ≠ 判据

用户的文字描述优先于模型读图。2026-11-16 踩过：把一段 3D 挥砍参考读成「长弧能量刃 + 碎片」，
用户直接否掉。判据里的数字必须来自 `ref-probe` 量出来的实测区间，不能来自"模型说是这样"。

## 4. 参考不足时怎么问

参考只有一张静帧、而需求会动（云要翻滚、电弧要闪）时，别拿静帧硬凑动效判据：
要么补帧（GIF/视频），要么把动效判据降级成 `noMetric` 并写明理由，交给人判。
