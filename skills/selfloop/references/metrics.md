# 闭环引擎 · 指标与口径

**什么时候读**：要定/改一个指标口径，或两个数比不出来、怀疑跨工具换算不一致。

> **唯一口径原则**：任何「差多少算变好」的讨论以本文件为准。
> 发现代码与本文件不一致时：**先改本文件，再改代码**——不要各自用各自的口径。
> 口径不对，后面所有搜索都是在优化一个错的函数。

---

## 1. 跨工具换算（最容易踩的坑）

```
pngStats 口径的 meanDiff  =  3 × g1diff 口径的 meanDiff      （每通道 MAE）
```

原因：`pngStats` 的差分子是 `Σ(|ΔR| + |ΔG| + |ΔB|)`、除数只算像素数；`g1diff` 的除数算 `3 × 像素数`。

实例：某份报告写 `meanDiff 5.04`（g1diff 口径）→ pngStats 口径是 **15.1**。

> **规则：跨文档、跨工具比数字之前先换算，否则结论错 3 倍。**
> 报告里写数字必须带口径名，例如「15.1（pngStats 口径）」。

---

## 2. 核心指标定义

```
对每个像素 p：
  d(p) = |ΔR| + |ΔG| + |ΔB|          // 0..765
  changed++  if d(p) > 6             // 约等于每通道平均 > 2

meanDiff  = Σ d(p) / N               // pngStats 口径
changePct = changed / N × 100        // 变化像素占比
```

- `meanDiff` 管「整体差多少」，单位是每像素平均通道和。
- `changePct` 管「有多少像素动了」，对局部小改动更敏感。
- 两者要一起看：`changePct` 高但 `meanDiff` 低 = 大片微小抖动（噪声）；反过来 = 少数像素剧烈变化（局部结构变化）。

**能测**：某一层/某次改动是否存在、落在哪些像素、回归是否意外变成 0。
**测不出**：改的方向对不对、好不好看、人眼是否可见。

---

## 3. 档位表（判「这次改动算不算数」）

| 级别 | `changePct` | `meanDiff`（pngStats 口径） | 判定 | 动作 |
|---|---|---|---|---|
| 无必要 | < 2% | < 2 | 几乎白给 | 关掉省性能；要保留必须写明理由 |
| 中间地带 | 2–15% | 2–12 | 有作用但需旁证 | 结合色种数 / 暖色 / 边缘密度再看 |
| 有效层 | 15–40% | 12–40 | 真在起作用 | 必须说明差异集中在哪 |
| 换物种 | > 40% | > 40 | 结构性改变 | 全图 + 差值图 + 「有意为之」的说明 |

三个档位坐标（2% / 15% / 40%）是**判「一次改动值不值得留」**的尺子，不是判「像不像目标」的尺子。判像不像用距离（见 `workflow.md` 第 3 步）。

## 4. 底噪：比换算更致命的坑

**没有这一步，上面所有阈值都是假判据。**

实测（同参数、同驱动、同模式，连续重跑两次）：`meanDiff` 刀光 **2.95**、火刀 **3.33**；不冻帧时峰值帧 IoU 只有 **0.08–0.31**。

含义两条：

1. **不冻帧的对比没有任何意义**——两次跑连峰值帧都对不上，测到的全是相位噪声。
2. 底噪 ≈ 3，而档位表把「< 2」判为无必要——**刻度比噪声还小**，等于拿噪声当结论。

修订后的判据：

```
有效差异  <=>  meanDiff ≥ max(3 × 底噪, 档位表阈值)
        且必须处于冻帧模式（同 t、同 seed、同驱动、同机型）
```

| 级别 | 含底噪约束的口径 | 判定 |
|---|---|---|
| 无法判定 | 未冻帧，或 `meanDiff < 3 × 底噪`（约 9） | **不许下结论** |
| 无必要 | 已冻帧且 `< 2` | 关掉省性能 |
| 中间地带 | 已冻帧且 `2–12` | 需旁证 |
| 有效层 | 已冻帧且 `12–40` | 真在起作用 |
| 换物种 | 已冻帧且 `> 40` | 结构性改变 |

> 底噪随场景与特效而变，**每个场景各自标定一次**（同参重跑 2–3 次取中位数），别把 3 当全局常数。

### 4.1 底噪要在「同一探针流程」内测

同一发特效，若用两种 step 序列，可能落到不同时刻：数字（`meanDiff` / `changePct`）能复现到小数点后两位，但 `MD5` 不同。

```
meanDiff / changePct  →  可跨流程参考
MD5 / 逐字节       →  只在同一流程内有效
```

**2026-11-12 修正**：真正的不变量是「**绝对时刻 + seed**」，不是 step 序列本身。`step(16, 20ms)` 与 `step(20, 16ms)` 都落在 320ms → 出图 SHA 完全相同。所以实践要求是：**显式算出落到的绝对毫秒并写进报告**；落不到同一时刻的数字一律不可比。

附带纪律：step 粒度要能整除目标时刻（320 / 440 / 700 用 20ms 才整除），否则取整落到邻帧，制造「假不同」。

## 5. 辅助指标

| 指标 | 工具 | 判什么 | 注意 |
|---|---|---|---|
| 色种数 | `pngPalette`（每通道右移 5 位量化后计数） | 硬色阶 / 脏色 | **场景类与 UI 类两套阈值，不可混用** |
| 亮度分布 | `pngStats` 桶 `>8 / >24 / >64 / >160` | 明暗是否断层 | **缺 `>80` 桶**，「暗部占比」目前量不了 |
| 确定性 | 同参连跑两次 | 截图是否可复现 | 要求 `meanDiff < 0.05`、`changePct < 0.1%`、冻帧 MD5 相同 |

**暖色谓词三处不一致**（归一化峰值 / 8bit `g ≥ b*0.9` / 少一个条件）——**比暖色阈值前，先声明用的是哪个工具**。

## 6. 数字为主，图为辅

| 用途 | 用什么 |
|---|---|
| 判据 / 闸门 / 回归 | **数字**（指标、哈希、像素统计） |
| 沟通 / 汇报 / 给人看 | 图 |
| 二者冲突 | **以数字为准**，并去查图为什么不对（多半是相位或缓存） |

图能证明「看得见」，数字才能证明「对得上」。所以证据包里「≥3 张 PNG」是防「没交付」，**判定合格看 `run.json` 里的数字**，不是看着像就行。

---

## 7. 未标定 = 不许当判据

以下三条**尚未标定**，写报告时可以提，**不许当验收判据**：

- 边缘密度 / 局部对比度（`edgeDensity`、`lcP90`）
- 时域判据（帧间抖动 ≤ 1.5× 参考）——只从 1 份影片反推，样本不足
- 启动耗时阈值——需 3 跑取中位数
- 过曝轴（`>160` 占比 + 高亮暖色占比的双阈值）——有想法、没标定
- 分块高频能量（8×8 块，>30% 块偏低判糊）——同上

**校准方法**：取 3 个好样本 + 3 个坏样本，阈值取两组间隙中点，并记录样本 ID。

⚠ **不要照抄外部文档给的峰值数字**（如「高动态峰值 2–3」）——我们是 HDR 源值，管线不同，数值不可移植。

## 8. 掩膜：先在主体上算，再谈数字（0.11.0 起，0.12.0 扩到四种口径）

> ⚠️ **醒目警告（0.12.0，有实验证据）**
> **`content` 掩膜按亮度圈，白天 / 雪地 / 亮背景 / 亮舞台会圈错**：它会圈到背景上（背景比主体亮），
> 或者只剩主体里那一小块白芯。第二轮实验的现场是后者——`luma:200` 时舞台天空 luma≈95~110、火焰体
> 中位数≈124，`luma>=200` 只剩枪口白芯：**对真主体 recall 只有 0.09~0.38**。
> **跨帧 / 跨变体比较请用 `roi` 或 `diff`**；`content` 只适合"亮主体 + 暗背景"。

两条实验的结论是同一个病：**指标没瞎，是分母瞎了**。火焰只占画面 3.8~6.4%，全帧统计把它稀释掉；换个题材/换个占屏比，同一个目标帧的距离就变了——实测出现过 `p=0.0034` 的假相关，纯粹是因为换了题材。

`metrics2.js` 的提取器统一支持 `opts.mask`，**所有统计都在掩膜内算**。四种圈法，按"稳"排序：

| `mode` | 写法 | 一句话 | 什么时候用 |
|---|---|---|---|
| `roi` | `{mode:"roi", rect:[x,y,w,h]}` | **固定矩形**，完全**不看像素内容** | 跨帧/跨变体比较的唯一稳口径（同一 ROI 在三张图上逐像素相同） |
| `diff` | `{mode:"diff", ref:"<空舞台.png>", delta:12}` | 与背景图做差分：`\|luma差\| > delta` 为前景 → 最大连通域 | 分不清"亮主体"与"亮背景"的正解 |
| `chroma` | `{mode:"chroma", predicate:{channel:"blue-minus-red", op:"<", value:-20}}` | 按**色度谓词**圈（暖主体 vs 冷背景） | 亮度分不开、颜色分得开 |
| `content` | `{mode:"content", luma:40}` | 按 `luma >= luma` 圈前景 → 最大连通域 | **只适合亮主体 + 暗背景**；见上面的警告 |

`chroma` 的谓词只认 7 个通道：`r / g / b / luma / blue-minus-red / red-minus-blue / saturation`，
比较符只认 `< <= > >=`。写错（通道名错、符号错、value 不是数字）一律**硬错**，绝不静默变成全图或空图。

公共字段：

| 字段 | 默认 | 一句话 |
|---|---|---|
| `dilate` | 1 | 方形（切比雪夫）膨胀半径，把主体外沿半透明的像素纳进来。**对 `roi` 也生效**（矩形会向外扩这么多像素） |
| `minAreaPct` | 0.2 | **百分数**（0.2 = 0.2%）。掩膜面积低于它就退回全图 |
| `none` | — | `{mode:"none"}` = 显式全图，等价于不写 `mask` |

三条硬规矩：

1. **回退不许静默**。面积不够时提取器照常给数（全图口径），但 `extractOne` 会在**这张图的返回对象**上写
   `maskFallback: true` 与 `maskInfo`（实际面积占比）。看到 `maskFallback` 就等于"这次量的是整帧，不是主体"，报告里必须写出来。
2. **圈错也要报**（0.12.0）。`content / diff / chroma` 圈出来的面积 <1% 或包围盒 <5% → `maskSuspicious: true`
   + `maskSuspectReasons[]`（写清踩了哪条门槛）。这条存在的理由是：圈错的掩膜**比没有掩膜更危险**——
   它不报错、不崩、照样给出"稳定一比"的数字，看起来非常专业。
3. **不写 `opts.mask` 就与升级前逐字节一致**。`roi` 越界会**夹紧并 warn**（`maskWarn[]`，同时带 `requested` 与生效值）——
   不静默裁掉、也不静默改用全图。

`maskInfo` 会带模式专属口径（`roi` 的实际矩形 / `diff` 的 ref 绝对路径与 delta / `chroma` 的谓词），
以及 **`maskHash`**（0.13.0：对掩膜位图做 FNV-1a，8 位十六进制；`mode:"none"` / 回退全图时为 `null`），
所以报告里能看出**这次到底用的是哪套圈法**——不是只写"用了掩膜"。

> **`maskHash` 是给哨兵用的**：`areaPct` / `bboxPct` 只说明"圈了多大"，说明不了"圈的是不是同一块像素"。
> 第二轮实验里三个不同变体圈出的都是那块枪口白芯（面积/包围盒一样），maskHash 才会把"冻住"照出来。
> 命令链路（`cmdloop.mjs`，0.13.0）默认用它做 `maskFrozen` 检测：同一轮里 ≥3 个"参数不同、观测 sha 不同，
> 但 maskHash 相同且掩膜内指标向量逐位相同"的候选 → **硬错**（换 `roi` / `diff` 口径）；只有 2 个 → warn。
> `roi` 不参与硬错：它的 maskHash 天然恒定，同组只能说明"指标对参数不敏感"，那是另一个病（只 warn）。
> `--no-mask-sentinel` 可关（会 warn 一句）。**截图链路（`iter.ps1`）没有这个哨兵**——见 §"两条链路"。

掩膜**没有**改的东西：`diag`（只读诊断块）永远是全图口径——它是历史字段的兼容垫，改它的口径会让老证据包的数字不可比。

### 8.1 实验现场（为什么 0.12.0 要加三种口径）

| 口径 | 掩膜面积 | 对真主体的 recall |
|---|---|---|
| 真主体 | 13.21% | 1.0（定义） |
| `content(luma:200)` | 0.39% | **0.03**（只剩白芯，且被标 `maskSuspicious`） |
| `diff(ref=空舞台, delta=12)` | 13.21% | **1.00** |
| `chroma(b-r < -20)` | 12.82% | 0.97（近白的高光芯按定义不是"暖色"，所以漏了 3%） |

最硬的证据不是 recall，是**逐位相同**：三个不同变体在三个时刻的掩膜内指标一模一样
（`7305.98|0.21296|0.11216`）——最大连通域在"枪口团"和"射线"之间跳，等于把不同变体量成同一块像素。

## 9. 三套量各管一件事：量化 / 噪点 / 细节（0.12.0 口径收缩）

上一代的 `posterizeRatio` / `hueBands` / `flatNoise`（实验侧临时实现，不在本仓库）对**肉眼明显可见**的人造 posterize
（逐像素抖动 + 硬切 4 档）只有噪声级反应，其中 `flatNoise` 是**零响应**——它的"3×3 极差 < 8"门限把噪点/台阶边
自己的像素排除掉了，这是结构性盲区，不是参数没调好。

### 9.1 `stepRatio`：**量化/剁档代理，不测细节**

硬切档在直方图上是**空档**（4 档就只有 4 个桶满、中间全空），跟像素落哪儿无关，所以它不怕稀释也不怕位移。

```
256 桶 luma 直方图（掩膜内）
断崖 = bin[i] > 0.05% 的像素数 且 bin[i+1] < bin[i] × 0.1
stepRatio = 断崖数 / 非空 bin 数
```

- 参数：`minBinPct:0.0005`（= 0.05%，是占比不是百分数）、`dropRatio:0.1`。
- 连续渐变 → **0**；4 档硬切 → **1.0**。
- ⚠️ **它只测"量化 / 剁档"，不测"细节"**。第二轮正对照失败：高斯模糊 `lapVar −99.7%` / 锐化 `+169%`
  （剂量单调、方向正确），而 `stepRatio` 在**模糊和锐化两个相反方向上同向下降**（−49~−80% 与 −51~−81%）。
  一个在"变平"和"变细"时都下降的量，量的不是细节量，是直方图断崖。
  **不得用于"更平 / 更细"的判断**；代码里连 `desc` 都写死了这句（`test/metrics.test.mjs` 有断言钉住它对模糊/锐化不敏感）。
- 标定来源：这两个数是实验里 P/R 正对照标出来的量级，不是拍脑袋。

### 9.2 `levelCount`：量化代理（唯一 luma 取值数）

```
levelCount = 掩膜内 luma 取整后**去重**得到的取值个数（0~256 的整数）
```

- 连续渐变 → **256**；4 档硬切 → **4**（实测差 64 倍）；8 档硬切 → 8。
- 它和 `stepRatio` 是一套的两个视角：`stepRatio` 看"直方图有没有空档"，`levelCount` 看"到底用了几档"。
- ⚠️ **同样只声称"量化代理"，不是细节指标**。已知边界（实测）：模糊会把取值个数压窄（同一张细节图上
  σ=1→95、σ=2→51），dither 会把它填回中间值（4 档 + ±2 级抖动 → 20）。所以它只适合
  **"连续 vs 硬切几档"** 这种比较，别拿去判"更平/更细"，也别拿它判"有没有 dither"。
- 正对照口径：**"连续 vs 硬切 4 档"**，不许混用模糊/锐化那套细节对照（两套混用等于又回到"拿错尺子"）。

### 9.3 `speckleFrac`：孤立点占比

```
对掩膜内每个像素 p：取 8 邻域 luma 的**中位数** med
| luma(p) − med | > speckleDelta（默认 24）→ 记一次
speckleFrac = 孤立像素数 / 掩膜内像素数
```

- 中位数对"自己是尖点"免疫 —— 所以孤立点**一定**被推出来，而平坦区/连续渐变里差值恒 ≈ 0。
- 对比老 `flatNoise` 为什么瞎：它数的是"3×3 极差 < 8 的平坦像素"，而一个噪点先把**自己那一格**的极差撑到 90，于是噪点越密、它越看不见（噪点把自己从统计里删掉了）。
- 连续渐变 → **0**；4% 孤立点 → **0.0403**。

### 9.4 正对照纪律：**细节指标必须双向**，量化指标只认"连续 vs 硬切"（0.12.0 升级）

> **新指标要先在"已知变坏"的合成图上翻得动，才有资格进判据。**

**声称"细节"的指标（现在只有 `lapVar`）必须做双向正对照**，三个条件缺一不可：

| 方向 | 要求 | 为什么 |
|---|---|---|
| 模糊（σ=1） | 指标**显著下降** | 已知更平 |
| 模糊（σ=2） | 比 σ=1 **更低**（剂量单调） | 只"掉一点"可能只是噪声，剂量单调才说明它在跟细节走 |
| 锐化（unsharp） | 指标**显著上升** | 已知更细 |

**只测一个方向不算标定**——`stepRatio` 的翻车正是"模糊和锐化同向下降"：只看模糊那一侧它完全合格。

`test/metrics.test.mjs` 用代码生成合成图（**不联网**）：

| 图 | 怎么造 | 用来钉什么 |
|---|---|---|
| `smooth.png` | 连续渐变（每列一个亮度，0~255 全覆盖） | 量化基准：无量化、无噪点 |
| `banded4.png` | 把 smooth 硬切 4 档 | 人造 posterize（`stepRatio` / `levelCount` 的正对照） |
| `speckled.png` | smooth + 间隔 5px 的孤立点（±90） | 人造噪点 |
| `det_base.png` / `det_blur1` / `det_blur2` / `det_sharp.png` | 三频叠纹理 / 高斯 σ=1 / σ=2 / unsharp(1.5) | **双向正对照**（细节指标） |
| `small_subject.png` / `subject_only.png` | 主体 57×57 细格占 5%，背景是**过得了 luma 门限的平坦灰** | 全帧稀释 vs 掩膜内 |
| `stage_bg.png` / `stage_fire.png` | 空舞台 + 暖主体（体 luma≈161、白芯 luma≈250、天空 luma≈101） | 还原实验现场：`content(luma:200)` recall 0.03 vs `diff` 1.00 |
| `warm_cold.png` | 暖块 + 冷背景 | `chroma` 谓词 |
| `tiny_subject.png` | 6×6 亮块（占 0.009%） | `maskFallback` |

实测（本仓库测试直接打印）：`stepRatio` 0 → 1.0；`levelCount` 256 → 4；`speckleFrac` 0 → 0.04032；
`lapVar` 原图 **455.5** → 模糊σ1 **155.85（−65.8%）** → 模糊σ2 **12.05（−97.4%）** → 锐化 **1191.46（+161.6%）**。

纪律由**清单 + 断言**双边钉住：

- `EXTRACTORS_WITH_POSITIVE_CONTROL` 里每加一个名字，本文件就得有一条真在标定它的断言；往注册表里塞一个没进清单的提取器 → 测试直接红（`checkLedger`）。
- `DETAIL_METRICS`（声称细节的指标）：必须真被 `assertBidirectional` 标定过，否则"双向纪律"那条红；**只测一个方向 / 剂量不单调会被当场拒**。
- `QUANT_METRICS`（`stepRatio` / `levelCount`）：清单与 `DETAIL_METRICS` 不许有交集（两套正对照不许混用）。

**怎么判断掩膜圈对了主体**（§8 的警告）：

1. 看 `maskSuspicious`——为 true 就**先信它**（面积 <1% 或 bbox <5% 基本就是圈到高光点了），换成 `roi`/`diff` 再量；
2. 看 `maskInfo.areaPct` 和主体在画面里的实际占屏比是否一个量级（差 3 倍以上就要怀疑圈到背景了）；
3. 掩膜内与全帧的同一指标**必须有明显差**——如果两者几乎相等，说明掩膜 ≈ 全图（要么没圈到，要么主体本来就铺满）；
4. 最硬的证据是**主体纯图对照**：把主体裁出来单独量一次，掩膜内的值应落在它的量级上（差异只该来自掩膜边缘那条环）。

## 10. 一句话

**判「有没有变」用 `meanDiff` / `changePct`（先减底噪），判「像不像」用距离（先过对抗关），判「好不好」只能靠人。**
