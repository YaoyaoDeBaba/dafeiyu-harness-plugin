# 闭环引擎 · 流程与判据

> 五步走：**活性扫描 → 选轴 → 搜索 → 证据包 → 半自动判定**。
> 每步都写「怎么算过」「不过说明什么」——**过不了就是过不了，不要改判据去迁就结果**。

---

## 第 1 步 · 参数活性扫描（先于任何搜索）

### 做什么

一个参数一次，改一档，出一次产物，比差值，记状态。

```
① 逐个参数改「一档」     其余保持默认，绝不累加
② 出一次产物             与最终验收同口径：同尺寸、同格式、同冻结状态
③ 比差值                 逐字节优先；只能像素级时先确认基线自跑两次差为 0
④ 记录                   状态 + 管哪个指标 + 灵敏度
```

四条纪律（少一条，测出来的都是噪声）：

1. **一次只动一个参数**——同时动两个，差值无法归因。
2. **差分锁状态**——同 seed、同绝对毫秒、同分辨率、同输入。
3. **每次从纯净基线重写配置**，不做增量，否则第 5 个参数带着前 4 个的残留被测。
4. **至少两档，且跨到默认点两侧**——只在默认点一侧测，会漏掉「默认点正好是峰/谷」。

「一档」怎么定：连续参数用默认值的 ∓10% / ∓20%；枚举参数挨个试；**默认值是 0 的乘式参数**要改用绝对增量定义档位，否则所有档位都退化成 0。

### 五分类（不是活/死二分）

| 状态 | 判据 | 处理 |
|---|---|---|
| **活** | 改一档有明显变化，且单调 | ✅ 可作搜索轴，按灵敏度排序 |
| **假** | 有变化，但变的是**评价条件**（挪时钟、放大量程、换单位），不是产物 | 🚫 拉黑。灵敏度往往全校最高，最容易被误当第一轴 |
| **非单调** | 有变化但来回摆（峰/谷/翻转） | ⚠️ 不进坐标下降；只能线搜索或单侧大步长 |
| **本相位死** | 当前时刻近似零变化，换个时刻就活 | ⚠️ 标「有条件活」，换相位复测，别当死删掉 |
| **死** | 改一档**零变化** | ❌ 剔除，**并查根因**（零变化几乎总是没接上线） |

### 判据表

| 观测 | 判定 |
|---|---|
| `Δ = 0`（逐字节全同） | 死 → 去查这个键到底有没有被读 |
| `Δ > 0` 且秩相关 `ρ = ±1` | 活且单调 → 可作轴 |
| `Δ > 0` 但方向中途翻转 | 非单调 → 只做线搜索 |
| 参数 A、B 产物完全相同 | 等价轴 → 只留一个 |
| 改 X 的产物 == 手动改另一条已知通道的产物 | 假轴 → 拉黑 X |

**抓假轴必须两个对照**：一个「通道全动」，一个「把该通道的几何/语义部分冻结」。只做前者，当参数只推进了通道的一部分（时钟走了、几何没走）时，会把假轴判成真轴。

### 失败含义

- 扫出 **0 根活轴** → 别搜索了，这是工程问题（参数路由没接通），先修路由。
- 扫出 **1–2 根轴** → 可以搜，但要接受「在 2 根轴上把指标压得很低，可能只说明另外几个方向没被约束」。
- 有 **假轴进了白名单** → 搜索会靠挪时钟降分，指标漂亮、画面没变好。这是最难自查的失败，务必做两个对照。

**成本**：`N 个参数 × k 档 + 1 次基准`，一次性。比一次错误搜索便宜一到两个数量级。

## 第 2 步 · 选轴

只从「活且单调」里选，**先分类再排序**（按灵敏度 `S = (max − min) / |基准值|` 排序，但 S 只用于排序、不能用于分类——最高 S 很可能属于假轴）。

- 轴数 ≥ 3：坐标下降更稳（实测约 35 次评估，降幅 ~86%）
- 轴数 = 2：随机重启略强（实测约 33 次评估，降幅 ~88%）
- 轴数 = 1：直接一维线搜索，别上通用搜索器

**失败含义**：白名单里混进等价轴，等于同一件事做两次，预算白花一倍。

## 第 3 步 · 搜索

- 预算 `-Budget` 按「一次 render + 一次 metric = 1 次评估」计，用完即停。
- 每轮都要能回答「这轮为什么往这个方向走」，曲线要能落盘。
- 目标来源两种：PNG 目标帧 / JSON 目标参数（内部先渲出目标帧）。
- 判据是**距离下降**，不是「像不像」：

```
d_prof = mean_k |m.prof[k] − t.prof[k]| / max(|t.prof[k]|, 0.15)
d_lap  = |m.lapVar − t.lapVar| / max(t.lapVar, 1)
d_warm = |m.warmFrac − t.warmFrac| / max(t.warmFrac, 0.2)
P      = 0.5  若核心占比为 0，或核心覆盖率 < 目标的一半
d      = (d_prof + d_lap + d_warm) / 3 + P
```

归一化基准是**目标帧**，不是样本集 min-max；方向固定「候选 → 目标」，**这套距离不对称，换个方向数字就变**。

**失败含义**：距离降了 70–90% 但观感更差——这不是搜索失败，是**指标不够**。见第 5 步的对抗门槛。

## 第 4 步 · 证据包

一次 run 必须留下六件，缺一件就算没跑：

| 文件 | 内容 |
|---|---|
| `curve.csv` | 每轮的距离与参数，能画曲线 |
| `best.json` | 最优参数 + 该点的指标包 |
| `report.md` | 结论 + 上面「必须写清」的那九项 |
| `shots\` | target / best / 逐轮缩略（缩略名里带距离，方便肉眼排序） |
| `logs\` | 每次评估的原始指标包 + 运行参数 |
| `base\` | 基线配置副本（事后要能一键回到起点） |

**判据**：把 `-Out` 目录原样交给别人，他不问你任何问题就能复跑——这才叫可复验。

**失败含义**：只有 best 图、没有 curve 和 logs 的 run，事后无法归因，等于一次性实验。

## 第 5 步 · 半自动判定（人点头）

### 必须依次过三关

1. **数字关**：距离降幅达标，且每轮曲线不是「一步到底然后不动」（那是撞上限或全死轴）。
2. **对抗关**：拿 best 派生一批劣化样本（加噪、模糊、降对比、压暗），**任何一个劣化样本的分数优于 best → 判定不通过**，先修指标再谈结果。
3. **人关**：把「目标 / best / 劣化样本」并排给人看，问一句「哪张更像目标」。人不同意 → **以人为准**。

### 为什么必须有第三关

实测：机器盲评 0/4，人 4/4；机器每次都选「更糊 / 更噪 / 更细更暗」那张，因为它把「变细变暗」当成了「更近」。对抗门槛只能证明「不会把同内容的糊版当更优」，**不能据此把距离升格成裁判**。

### 判定输出

不是一句「收敛了」，而是三句话：

- 降了多少（距离降幅 X%，用了 N 次评估）
- 参数误差多少（如 `widthPx` 误差 3%、`distM` 误差 33.6%——**参数误差和距离降幅是两件事，都要报**）
- 人怎么看（通过 / 不通过 / 需要再看）

**失败含义**：把「距离降幅」当验收依据，是这套系统最常见的误用。降 73% 同时画面更糊，有实证。
