# 闭环引擎 · 坑位（按症状查）

> 用法：出问题时你脑子里想的是**症状**，不是编号。所以主键是症状。
> 顺序：① 按「你看到了什么」找最像的一行 → ② 看根因判断是不是同一个病 → ③ 看「现在的防线」，防线空的就是还没补 → ④ 修完发现新症状，**加一行**，别另开文档。

四类：**构建 / 参数 / 测量 / 传递**。

---

## 构建类（代码没错，产物是旧的 / 报错看不懂）

| 症状 | 根因 | 看起来像什么 | 防线 |
|---|---|---|---|
| 构建零报错，但页面某模块未定义 / 偶发 undefined | 清单只认「加载期可达」的引用：跨模块调用写进方法体，建不出依赖边 | 一切正常，只有运行时偶尔崩 | 强制重建清单（删掉旧清单再构建）+ 核对索引顺序 |
| 改了依赖顺序，构建还是老样子 | 清单没重建（构建器只在缺失时才重建） | 改完像没改 | 看构建输出有没有「已重建 / 环 0 / 顺序违规 0」 |
| ps1 脚本解析报错 / 中文乱码 | 掉了 UTF-8 BOM，PowerShell 5.1 按 ANSI 读 | 别人能跑你不能跑 | 校验首三字节 `239,187,191` |
| 闸门显示「通过」，但东西其实是坏的 | 断言只 `log()` 不 `exit 1` | 一片绿 | 必须真阻断；**新增断言要验「故意弄坏能红」** |
| 产物名对不上，页面加载旧文件 | 改名后没人同步引用 | 数字确实为 0，看着像真结论 | 验收前检查产物名一致性 |

## 参数类（改了没反应 / 一改就「变好」）

| 症状 | 根因 | 看起来像什么 | 防线 |
|---|---|---|---|
| **改了配置，画面一个像素都没变** | 参数没接通（上游只按位置传了少数参数，同名配置键进不去） | 以为「调得不够」，反复调 | **先跑活性扫描**；已知有一批参数是逐字节死的 |
| **某个参数特别灵，一调就「变好」** | 假轴：它只拨了渲染时钟，不改画面内容 | 灵敏度表排第一，像根好轴 | 拉黑；用「同参数 vs 换时刻」两个对照闭环验证 |
| **搜索怎么调都不动** | 三种可能：全死轴 / 默认点就是极值 / 非单调 | 曲线一条直线 | 活性扫描 + 一维响应曲线；非单调轴只做线搜索 |
| **调完更糊、更暗，但指标说「更近」** | 距离对模糊/噪声不敏感 | 数字漂亮、观感变差 | 对抗样本门槛；判据只认数字、**最终裁定交人** |
| 两根轴各扫一遍，等于同一件事做两次 | 等价轴（同一恒等式） | 预算白花一倍 | 写恒等式 + 一张同图验证，只留一个 |
| 结论过几天自己失效了 | 参数路由改过 / 配置键改名 / 换渲染管线，「轴悄悄死掉」且不报错 | 昨天能调的今天不动 | 任何路由改动后**重跑活性扫描**，表进版本控制 |

## 测量类（数字不可信 / 图数打架）

| 症状 | 根因 | 看起来像什么 | 防线 |
|---|---|---|---|
| **两次跑同一个场景，数字对不上** | 落到了不同时刻（相位不同）→ 粒子位置不同 | 以为改坏了 | **锁绝对毫秒 + seed**；step 粒度能整除到同一时刻即可 |
| **截图和数字矛盾** | 截图可能是旧画面（异步/缓存/读错帧） | 图看着对、数不对（或反之） | **数字为主、图为辅**；冲突时以数字为准再查图 |
| **底噪比要测的差异还大** | 没冻帧 / 没标底噪 | 什么都是「差不多」 | 同参重跑 2–3 次取中位数当底噪；差异要 ≥ 3× 底噪 |
| 你觉得对，用户觉得不对 | 共用标签页/缓存，或看的是不同档位 | 各说各话 | 报告写明 URL + 档位 + 分辨率 + 绝对毫秒；必要时让用户抓现场 |
| 「零变化」和「弱活」混为一谈 | 参数还进了别的归一化通道，有 ≤1–2% 像素微差 | 判定「没接上线」去改路由，白跑一趟 | 像素级给数值；写「本相位弱活 / 近死」并附另一相位的数字 |
| 跨工具比数字，结论差 3 倍 | `pngStats` 与 `g1diff` 的除数不同 | 两边报告都「对」 | 比之前先换算：`pngStats = 3 × g1diff`，并写清口径名 |

## 传递类（结论传出去就变形）

| 症状 | 根因 | 看起来像什么 | 防线 |
|---|---|---|---|
| **拿验收页一测，「特效根本没工作」** | 假验收页：引用了改名前的产物，模块 undefined | 数字为 0，看着像真结论 | 验收页也要过「产物名对得上」检查 |
| **两份报告互相打架** | 旧报告被取代但没标 | 不知道哪个是当前状态 | 首行 `STATUS: SUPERSEDED` + 第二行 `SUPERSEDED-BY: <新报告>` |
| **修一个 bug 引出两个新问题** | 靠加「保险」兜异常，而不是修根因 | 按下葫芦浮起瓢 | 对「未消费的配置键」要**报错**而不是静默；补丁必须带回归断言 |
| 交接后对方复跑不出来 | 报告没写 seed / 时刻 / 档位 / 端口 | 「我这边是好的」 | 报告强制九项：seed、绝对毫秒、档位、分辨率、端口/CDP、命令原文、目标来源、白名单、预算用量 |

## 三条「暂无防线」的缺口

| 缺口 | 后果 | 建议 |
|---|---|---|
| 过曝轴 | 有 bloom、有亮度，但没有一根判「白成一块」的轴 | `>160` 占比 + 高亮暖色占比双阈值；**先拿 3 好 3 坏标定**，别照抄外部峰值数字 |
| 测试坑分类 | 「测量类」此前完全没有类目，同样的坑反复踩 | 底噪/相位/假轴/共用标签页统一归到这里 |
| 「未消费键」报错 | 死参数静默被吞，谁调都白调 | 把已知的 E-DATA 模式推广到参数路由：键没被消费就报错 |

---

## 三条最贵的教训（如果只能记三条）

1. **`Δ = 0` 不是「这个参数不重要」，是「它没通电」。** 先查根因，别写结论。
2. **不锁绝对时刻的对比，测的全是相位噪声。** 同版本不同帧的差，可以比版本之间的差还大。
3. **距离降幅再高也不能当验收。** 它会对模糊和噪声让步；成品必须人点头。
