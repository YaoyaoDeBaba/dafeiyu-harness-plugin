# 特效参数闭环产线

## 这是什么

给定「想要的样子」——一张目标帧，或一组目标数值——自动找出最接近的参数组合，**几十秒量级**出结果，并留下可复验的证据包。

它只解决**形**：粗细、长度、节奏、面积、亮度这类能算的物理量。
它不解决**色 / 质 / 味**，也不替人判断成品好不好看。

## 开工前先确认三件事（缺一个就别开始）

1. 有能跑通的回路：**改配置 → 冻帧出图 → 算指标**。本项目里是 `_镜像\<你的分支>\client\` 下的 `vfx.json` + 实验室场景 + 本地静态服。
   插件版把入口放在包内 `harness/`，client 位置由环境变量 `%VFX_LOOP_CLIENT%`（或 `-Mirror`）给，包里不含任何本机路径。
   **环境**：Node ≥ 22.19；首装要浏览器 —— 用系统 Edge 零下载，走 Playwright 的 Chromium 约 740 MB（只要无头约 290 MB，`npx playwright install --only-shell chromium`）。
2. 有一个具体目标：**一张 PNG 目标帧**，或**一份 JSON 目标参数**（如 `{"widthPx":32,"distM":3.6}`）。
3. 有一个能写的输出目录（证据包落这里），且**不覆盖**别人的 run 目录。

## 五条硬规则（烧过钱换来的，不许绕过）

### ① 没做参数活性扫描，不许开始搜索

参数表 ≠ 生效参数。一个「看起来有几十个旋钮」的系统，实测可能只有几根真轴，其余改了输出**逐字节相同**。
（本项目就经历过：修路由前 2 根真轴 / 13 个死参数；修好后 12 根可搜索轴，其中 6 个复活、7 个确认无解。**这个数字会随管线变化，别抄，扫一遍就有**。）
不先扫描就搜索，代价是：预算花在死参数上、把「没接通」误判成「算法不行」、还可能让搜索学会作弊。
→ 扫描做法与五分法见 `references/workflow.md` 第 1 步。

### ② 对比必须锁「绝对毫秒 + seed」，不是锁「帧数」

可比的充要条件：**同一个 seed + 落到同一个绝对时刻 + 同档位 + 同分辨率**。
`step(16, 20ms)` 和 `step(20, 16ms)` 只要都落在 320ms，出图 SHA 可以完全相同；反过来，落到 340ms 和 320ms 就是两个世界——**同一版本不同时刻的差，常常比版本之间的差还大**。
所以报告里写的必须是「320ms」，不是「第 16 帧」。

### ③ 判据只认数字，图只用于给人看

截图的坑：异步渲染、缓存、读错帧，都可能让你拿到一张**旧画面**。
- 判据 / 闸门 / 回归 → 只认数值（指标、哈希、像素统计）
- 沟通 / 汇报 / 给人看 → 图
- 两者冲突 → **以数字为准**，再去查图为什么不对

### ④ 闸门新增断言必须验「故意弄坏能红」

断言只 `log()` 不 `exit 1`，闸门就形同虚设——外面很多范本就栽在这。
新增一条断言后，必须现场做一次反证：**造假数据 / 删图 / 写坏一行 → 必须 FAIL 且退出码非零**。验不过的断言等于没加。

### ⑤ 对抗样本（噪声 / 模糊）不得被判为更优

距离类指标对「糊」和「噪」不敏感，实测会**优选更糊更暗的那张**（机器盲评 0/4，人 4/4）。
所以每次出 best，都要再拿一批劣化样本（加噪、高斯模糊、降对比）去比：**只要有一个劣化样本的分数优于 best，就不许把这次结果交出去**，先修指标。

## 标准流程（每步的判据与失败含义在 references/workflow.md）

```
1 活性扫描 → 2 选轴 → 3 搜索 → 4 证据包 → 5 半自动判定
     ↑                                  |
     └── 换了渲染管线 / 参数路由后重跑 ──┘
```

五步的产物：一张参数表（状态/管哪个指标/灵敏度）→ 一份白名单（2–3 根轴）→ 曲线 + 最优参数 → 六件套 → 一句人话结论。

## 在本项目里怎么跑

入口是插件包里的迭代器（`harness/iter.ps1`；宿主/项目里另存的 T3/T4 副本是同一份脚本的历史拷贝，行为一致）：

```powershell
# 先让它知道你的 client 在哪（包里不含任何本机路径）
$env:VFX_LOOP_CLIENT = '<你的 client 根目录>'

# 目标是 png 帧
pwsh -File <包目录>\harness\iter.ps1 -Adapter <包目录>\adapters\fire-ray.json `
     -Target .\target.png -Params widthPx,distM -Budget 60 -Out .\runs\r1

# 目标是数值（内部先渲出目标帧）
pwsh -File <包目录>\harness\iter.ps1 -Adapter <包目录>\adapters\fire-ray.json `
     -Target '{"widthPx":32,"distM":3.6}' -Params widthPx,distM -Budget 60 -Out .\runs\r1
```

一次 run 产出（都在 `-Out` 下）：`curve.csv`（每轮距离）、`best.json`（最优参数）、`report.md`、`shots\`（target / best / 逐轮缩略）、`logs\`（每次评估的指标包）、`base\`（基线配置副本）。

**纪律**：只改镜像里的 `vfx.json`（本体拒写，前后交哈希）；浏览器用独立 `--user-data-dir`、按 PID 收尾；静态服端口和 CDP 端口各 run 独占，别抢别人的。
**进程卫生**：`capture.mjs` 挂了父进程死亡看门狗（每 10s 查一次，父没了就 `taskkill /T /F` 整棵树）+ 关闭时杀树 + 启动时只清「父进程已不存在」的自家孤儿。所以宿主被强杀也不会留下占端口的 `--headless` 浏览器；**判据是父进程没了，不是跑了多久**，别自己再加"超时杀"。profile 落在 `%TEMP%\dsh-vfx-loop\`。

## 报告里必须写清的东西

不写这些，结论不可复验，等于没跑：

`seed` ｜ 绝对时刻（ms）｜ 画质档（`-Tier`）｜ 分辨率 ｜ 端口 / CDP ｜ 命令原文 ｜ 目标来源（png 还是 json）｜ 白名单（哪几根轴）｜ 预算用掉几次。

## 什么时候别用它

| 情况 | 为什么不行 |
|---|---|
| **想全自动交付** | 指标能自动调「形」，不能判断好坏。实测盲评机器 0/4、人 4/4；把「变细变暗」当成「更近」。必须人点头。 |
| **跨题材直接套** | 只在单一特效题材上验证过（一条火柱类特效）。换题材要先重跑活性扫描，且判据阈值要重新标定。 |
| **要求美术级神似** | 距离只配做粗筛 / 报警。颜色、质感、笔触、光的层次它一概测不出来。 |
| **目标本身是错的** | 目标帧若是旧画面或错档位，闭环会非常认真地收敛到一个错的东西。先验目标。 |
