# 闭环产线 · 指标与口径

> **唯一口径原则**：任何「差多少算变好」的讨论以本文件为准。
> 发现代码与本文件不一致时：**先改本文件，再改代码**——不要各自用各自的口径。
> 口径不对，后面所有搜索都是在优化一个错的函数。

---

## 1. 跨工具换算（最容易踩的坑）

```
pngStats 口径的 meanDiff  =  3 × g1diff 口径的 meanDiff      （每通道 MAE）
```

原因：`pngStats` 的差分子是 `Σ(|ΔR| + |ΔG| + |ΔB|)`、除数只算像素数；`g1diff` 的除数算 `3 × 像素数`。

实例：某份报告写 `meanDiff 5.04`（g1diff 口径）→ pngStats 口径是 **15.1**。

> **规则：跨文档、跨工具比数字之前先换算，否则结论错 3 倍。**
> 报告里写数字必须带口径名，例如「15.1（pngStats 口径）」。

---

## 2. 核心指标定义

```
对每个像素 p：
  d(p) = |ΔR| + |ΔG| + |ΔB|          // 0..765
  changed++  if d(p) > 6             // 约等于每通道平均 > 2

meanDiff  = Σ d(p) / N               // pngStats 口径
changePct = changed / N × 100        // 变化像素占比
```

- `meanDiff` 管「整体差多少」，单位是每像素平均通道和。
- `changePct` 管「有多少像素动了」，对局部小改动更敏感。
- 两者要一起看：`changePct` 高但 `meanDiff` 低 = 大片微小抖动（噪声）；反过来 = 少数像素剧烈变化（局部结构变化）。

**能测**：某一层/某次改动是否存在、落在哪些像素、回归是否意外变成 0。
**测不出**：改的方向对不对、好不好看、人眼是否可见。

---

## 3. 档位表（判「这次改动算不算数」）

| 级别 | `changePct` | `meanDiff`（pngStats 口径） | 判定 | 动作 |
|---|---|---|---|---|
| 无必要 | < 2% | < 2 | 几乎白给 | 关掉省性能；要保留必须写明理由 |
| 中间地带 | 2–15% | 2–12 | 有作用但需旁证 | 结合色种数 / 暖色 / 边缘密度再看 |
| 有效层 | 15–40% | 12–40 | 真在起作用 | 必须说明差异集中在哪 |
| 换物种 | > 40% | > 40 | 结构性改变 | 全图 + 差值图 + 「有意为之」的说明 |

三个档位坐标（2% / 15% / 40%）是**判「一次改动值不值得留」**的尺子，不是判「像不像目标」的尺子。判像不像用距离（见 `workflow.md` 第 3 步）。

## 4. 底噪：比换算更致命的坑

**没有这一步，上面所有阈值都是假判据。**

实测（同参数、同驱动、同模式，连续重跑两次）：`meanDiff` 刀光 **2.95**、火刀 **3.33**；不冻帧时峰值帧 IoU 只有 **0.08–0.31**。

含义两条：

1. **不冻帧的对比没有任何意义**——两次跑连峰值帧都对不上，测到的全是相位噪声。
2. 底噪 ≈ 3，而档位表把「< 2」判为无必要——**刻度比噪声还小**，等于拿噪声当结论。

修订后的判据：

```
有效差异  <=>  meanDiff ≥ max(3 × 底噪, 档位表阈值)
        且必须处于冻帧模式（同 t、同 seed、同驱动、同机型）
```

| 级别 | 含底噪约束的口径 | 判定 |
|---|---|---|
| 无法判定 | 未冻帧，或 `meanDiff < 3 × 底噪`（约 9） | **不许下结论** |
| 无必要 | 已冻帧且 `< 2` | 关掉省性能 |
| 中间地带 | 已冻帧且 `2–12` | 需旁证 |
| 有效层 | 已冻帧且 `12–40` | 真在起作用 |
| 换物种 | 已冻帧且 `> 40` | 结构性改变 |

> 底噪随场景与特效而变，**每个场景各自标定一次**（同参重跑 2–3 次取中位数），别把 3 当全局常数。

### 4.1 底噪要在「同一探针流程」内测

同一发特效，若用两种 step 序列，可能落到不同时刻：数字（`meanDiff` / `changePct`）能复现到小数点后两位，但 `MD5` 不同。

```
meanDiff / changePct  →  可跨流程参考
MD5 / 逐字节       →  只在同一流程内有效
```

**2026-11-12 修正**：真正的不变量是「**绝对时刻 + seed**」，不是 step 序列本身。`step(16, 20ms)` 与 `step(20, 16ms)` 都落在 320ms → 出图 SHA 完全相同。所以实践要求是：**显式算出落到的绝对毫秒并写进报告**；落不到同一时刻的数字一律不可比。

附带纪律：step 粒度要能整除目标时刻（320 / 440 / 700 用 20ms 才整除），否则取整落到邻帧，制造「假不同」。

## 5. 辅助指标

| 指标 | 工具 | 判什么 | 注意 |
|---|---|---|---|
| 色种数 | `pngPalette`（每通道右移 5 位量化后计数） | 硬色阶 / 脏色 | **场景类与 UI 类两套阈值，不可混用** |
| 亮度分布 | `pngStats` 桶 `>8 / >24 / >64 / >160` | 明暗是否断层 | **缺 `>80` 桶**，「暗部占比」目前量不了 |
| 确定性 | 同参连跑两次 | 截图是否可复现 | 要求 `meanDiff < 0.05`、`changePct < 0.1%`、冻帧 MD5 相同 |

**暖色谓词三处不一致**（归一化峰值 / 8bit `g ≥ b*0.9` / 少一个条件）——**比暖色阈值前，先声明用的是哪个工具**。

---

## 6. 数字为主，图为辅

| 用途 | 用什么 |
|---|---|
| 判据 / 闸门 / 回归 | **数字**（指标、哈希、像素统计） |
| 沟通 / 汇报 / 给人看 | 图 |
| 二者冲突 | **以数字为准**，并去查图为什么不对（多半是相位或缓存） |

图能证明「看得见」，数字才能证明「对得上」。所以证据包里「≥3 张 PNG」是防「没交付」，**判定合格看 `run.json` 里的数字**，不是看着像就行。

---

## 7. 未标定 = 不许当判据

以下三条**尚未标定**，写报告时可以提，**不许当验收判据**：

- 边缘密度 / 局部对比度（`edgeDensity`、`lcP90`）
- 时域判据（帧间抖动 ≤ 1.5× 参考）——只从 1 份影片反推，样本不足
- 启动耗时阈值——需 3 跑取中位数
- 过曝轴（`>160` 占比 + 高亮暖色占比的双阈值）——有想法、没标定
- 分块高频能量（8×8 块，>30% 块偏低判糊）——同上

**校准方法**：取 3 个好样本 + 3 个坏样本，阈值取两组间隙中点，并记录样本 ID。

⚠ **不要照抄外部文档给的峰值数字**（如「高动态峰值 2–3」）——我们是 HDR 源值，管线不同，数值不可移植。

---

## 8. 一句话

**判「有没有变」用 `meanDiff` / `changePct`（先减底噪），判「像不像」用距离（先过对抗关），判「好不好」只能靠人。**
