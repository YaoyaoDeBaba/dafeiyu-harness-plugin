## 一、十一条硬契约（本地检查全查不出，真机必炸）

| # | 契约 | 症状 | 规避 |
|---|---|---|---|
| 1 | VS/FS 共享 uniform 精度不一致 | 链接期 Precisions of uniform differ | 两边都显式 uniform highp（VS 默认 highp，FS 默认 mediump） |
| 2 | fwidth/dFdx/dFdy 进了 VS | 编译失败（连只定义没调用的公共块也会炸） | 带导数的函数单独成块，只拼进 FS |
| 3 | GLSL 保留字当标识符 | Illegal use of reserved word | patch/sample/filter/common/buffer/shared/active/partition/subroutine/noperspective/half/fixed/unsigned/long/short/double/superp/packed 全部避开 |
| 4 | 类型维度不匹配 | dimension mismatch / cannot convert | 特别注意 vec2 hash21(float) 返回 vec2，别赋给 float；ES 3.00 禁 int→float 隐式转换 |
| 5 | 报错行号是拼接后的 | 定位错行 | 文件行 ≈ 报错行 − 公共块行数（公共块行数逐 program 不同） |
| 6 | attribute 没写 layout(location) | 静默错位（增删 in 时画面错但不报错） | 全部显式 layout(location = N) |
| 7 | 用了没声明的标识符 | undeclared identifier | 本地静态扫描不可靠；以真机编译为准，报错就贴行号修 |
| 8 | 禁 `fract(sin(x) * 43758.5453)` 哈希 | 跨 GPU 图案不一致，破坏同 t 同画面 | 换确定性哈希（见 §二）——同 t 两次截图像素 diff 必须 = 0 |
| 9 | `max(fwidth(d), 0.0008)` **逐字契约、整份 shader 只许出现一处**（**注释里抄一遍也算一处**） | 兼容层的字面量替换只改第一处；第二处残留 → WebGL1 上整层编译失败 | 收成唯一入口函数（如 `vkAAWidth()`），其它地方只调用；注释里也别复述这段字面量 |
| 10 | for 循环上界必须常量（兼容层是 ES 100 子集） | `for(i < uniformLayers)` 编译失败 | 写死最大次数 + `if (i >= oct) break;` 前缀截断；改层数 = 构建期替换 |
| 11 | 禁反向 smoothstep（`edge0 >= edge1` 是未定义行为） | 不同驱动出不同结果，甚至 NaN | 写 `1.0 - smoothstep(lo, hi, x)` |

**这版相比旧「八条硬雷」新增的三条（9/10/11），为什么必须进表**：旧表停在「编译能过」，这三条管的是「编译能过但**构建期替换 / 驱动差异**会阴你」——

- **第 9 条**：兼容层的文本替换没有全局标志，只替换**第一处**匹配。所以「多写一次 fwidth 保护」不是冗余，是**故障源**；更要命的是有人把公式抄进注释"留个说明"，注释里的那一段也会被替换掉，于是真正的代码那处没被换。这条是三轮真机里最难查的一类（现象是「本地好好的，装到兼容层就整层黑」）。
- **第 10 条**：原生 300 能写动态循环，WebGL1 兼容子集不能。同一份代码在两处编译，一处过一处炸。
- **第 11 条**：反向 smoothstep 是规范未定义行为，不报错、不告警，换一台机器结果变了——它破坏的是「同 t 同画面」这条底线。

> 若有 GLSL 静态检查器，它能覆盖前 9 类里的大部分；**第 10、11 类与下面三条铁律查不出**，只能人工自查 + 真机快检。

## 二、确定性哈希（跨 GPU 一致）——分两种宿主，别搞混

### 宿主 A：原生 GLSL ES 300 页面（可写 in/out/layout）

用整数 PCG，跨驱动位级一致：

```glsl
uint pcg(uint v){
    uint s = v * 747796405u + 2891336453u;
    uint w = ((s >> ((s >> 28u) + 4u)) ^ s) * 277803737u;
    return (w >> 22u) ^ w;
}
float hash11i(uint v){ return float(pcg(v)) * (1.0 / 4294967295.0); }
```

### 宿主 B：只做文本替换的 WebGL1 兼容层（案例 A 的宿主）

⚠️ **重要约束**：某些宿主的运行时只做四处文本替换（`attribute`→`in`、`varying`→`in/out`、`texture2D`→`texture`、`gl_FragColor`→输出变量），**没有原生 300 分支**。因此任何带 `#version`、`in/out`、`uint`、`layout(...)` 的片段贴进去都会编译失败——**整数 PCG 在这种宿主里用不了**。

宿主 B 里用「无 sin 的浮点哈希」（godot-shaders / ashima 系的做法）：

```glsl
// 无 sin、只用 fract 与乘加，跨驱动稳定；可直接贴进只做文本替换的兼容层
float hash11(float p){
    p = fract(p * 0.1031);
    p *= p + 33.33;
    p *= p + p;
    return fract(p);
}
float hash12(vec2 p){
    vec3 p3 = fract(vec3(p.xyx) * 0.1031);
    p3 += dot(p3, p3.yzx + 33.33);
    return fract((p3.x + p3.y) * p3.z);
}
```

### 第 9 条的字面契约细节（单独展开，因为它最阴）

1. 写法必须**逐字符一致**（空格、参数名都不能改），否则替换不命中；
2. **整份 shader 只能出现一处**——收成唯一入口函数，其它地方调用它；
3. **注释里也不要复述这段字面量**：替换是纯字符串操作，认不出注释；
4. 想多写一处「保护」的正确做法是加一个函数，不是加一个字面量。

## 三、三条实现铁律（2026-11-15 第一回合真机实测）

前两节管的是「shader 写错」，这三条管的是「**画法**本身错了」——都能编译通过、都不报错、都在画面上留一个说不清的症状。上一轮 12 支的实现里，这三条各坑过一次。

### 铁律 1：每个特效的 `draw()` 必须 `gl.useProgram`

- **不做的后果**：所有 uniform 静默丢弃（不报错），并且用台上**残留的 program** 画。
- **症状**：灰板一块、`t` 怎么改画面都不动、探针量出来全是常数——排查时会怀疑参数没接通/冻结失败，实际是程序没绑定。
- **自查**：`draw()` 里第一件事就是 `gl.useProgram(this.program)`；改了 program 之后所有 uniform 重设一遍。

### 铁律 2：极径 / 角度绝不做成 varying

- **不做的后果**：billboard 四角的 `length(loc)` 恒等 → 整张 quad 的插值结果是**常数** → 靠它定形的部件（圆盘、环、径向衰减的一切）**整块消失**或糊成一个色块。
- **根因**：varying 是在**四个顶点之间**插值的；而四个顶点到相机中心（或到 quad 中心）的距离本来就相等，插出来自然处处相等。
- **正确做法**：片元里用 `vLocal`（或直接用 `gl_FragCoord` / 传进来的局部坐标）**现算**极径与角度；varying 只传"每个顶点确实不同"的量（局部 xy、uv）。

### 铁律 3：quad 的四条边界扫描必须**精确为 0**（不是「很小」）

- **不做的后果**：「很小」= 0.001 也算有。加法层的 `exp()` 尾巴会把底抬起来，四条直边一旦被框出来就极其显眼（一整块方形亮边）。
- **症状**：成品外围出现一圈规则的正方形轮廓；关掉某个部件就消失。
- **正确做法**：边界处让 alpha **跳到 0**（`step`/硬 clamp 到 0），不要用「趋于 0」的衰减函数去近似。

> 这三条的共同点：**都不是语法错误，都是"纸上对、台上错"**。所以验收只能靠真机出图——静态检查、mock GL、解析器都看不到它们。

## 四、可观测性：uDebug 六档（强烈建议每个特效都留）

```glsl
uniform int uDebug;  // 0=成品 1=距离场 2=法线 3=材质或部件 id 4=步数/迭代 5=遮罩/alpha 6=光照项
```

出问题时：先拍 uDebug=1/3/5 三张，一眼看出是距离场算错、还是遮罩断链、还是 id 串了。
实战价值：有一轮「白卡片」bug 排查了四轮真机出图，有这个档位一张探针图就能定位。
铁律 1 的症状（灰板 + t 无反应）也能被它一眼指出来：uDebug 全档都是同一个灰，说明根本没进到着色器。

## 五、NaN 与边缘安全

- NaN 源清单：atan(0,0)、负数 pow/sqrt、normalize(vec3(0))（退化几何的极点法线最常犯）；
- 致命细节：max(NaN, 0.0) 在 GLSL 里返回 0.0（NaN 被吞成 0），step(d, NaN) 恒为 1——NaN 会静默污染整条 min/step 记账链；修法是用显式 if (d < bestD) 而不是 min，并在入口守卫 (d >= 0.0 && d < 1e8)；
- 面片必须盖住内容：可见半径 < quad 半宽，否则边缘被切出直边（踩过：爆光球圆盘 1.7r 画在 1.35r 的 quad 里 → 整块白卡片）；
- 导数不能进非一致分支/循环：fwidth 在分支里结果未定义。

## 六、性能与预算（写进需求书时的措辞）

- 写成上限 + 超了先砍谁，不要写死数字：例「FBM ≤6 层，移动端 3 层；超预算先砍粒子数，其次砍噪声层数」；
- 循环边界尽量是常量（见第 10 条）；兼容层里"构建期字符串替换成常量"比运行时动态条件既快又合法；
- 顶点着色器可以预算相邻 UV（如流体模拟把 vL/vR/vT/vB 在 VS 算好传 FS），片元里省多次乘加；
- 实例化：属性只带最小集（起点、终点、时间、生命周期、半径、种子）；上千粒走 drawArraysInstanced。
