## 0. 案例 A 的舞台事实（示例宿主）

- 评测台没有 tone mapping、没有 bloom、没有后处理抗锯齿。
- 任何亮度 >1.0 的自发光都被直接裁成纯白 → 发光层峰值压到 ≤1.0，层次靠色值给，不靠亮度堆。
- 720p 下屏幕宽度小于 6 像素的部件基本看不见（已实测：1~2px 的雷体=看不见）。
- 像素尺子（2026-11-15 修正，旧说法「1 世界单位 ≈ 120~140 px」是错的）：`pxPerUnit(depth) = canvasH / (2 * depth * tan(fovY / 2))`。本机位实测**命中点 ≈ 92 px/单位**；**贴地部件沿视线径向被压到 13~38 px/米**（相机俯角仅约 13°，径向压缩系数 ≈ sin(13°) ≈ 0.225）。所以贴地线宽要按径向压缩后的像素判可见性，别拿命中点的 92 去乘。公式推导与两张换算表见 `demand-translator.md` §6.1，按 R/L 换算时一律先换像素再判。
- 没有相机控制（震屏只能抖特效几何）、没有时间轴停顿钩子（顿帧只能用白闪平台近似）。

## 1. 混合口径（决定卡渲成败的一条）

- 不透明色块（主体、描边、贴地面）→ 预乘 alpha（ONE, ONE_MINUS_SRC_ALPHA）。
- 光（白芯、光晕、星芒、火花、屏幕闪光）→ 加法。
- 主体绝对不许走加法：加法叠加时 RGB 三通道一起推满，蓝/紫/橙一律烧成纯白。上一批三个实现在这条上全军覆没。
- 正确绘制顺序：光晕(加法) → 外沿(预乘) → 主体(预乘) → 白芯(加法) → 火花/闪光(加法)。

## 2. 色阶与描边

- 三段硬边：按阈值切档，过渡宽度 = fwidth 级（屏幕 2~4px），档内纯色。
- 描边 = 几何反向外扩（同一份网格放大 + 正面剔除 + 先画暗色），不许后处理描边、不许片元里做边缘检测。

## 3. 形状与噪声

- 形状由参数化折线 / 几何包络决定；噪声只做 ≤10~15% 的边缘扰动。
- 噪声直接乘宽度/透明度定形 = 劣质手游特效的标志。
- 端点必须钉死在世界坐标（命中点/敌人位置）。

## 4. 尺寸口径

- 以技能长度 L / 半径 R 为单位给相对尺寸。
- 每个关键部件都要能回答：这在 1280x720 下是多少像素、能不能看见。

## 5. 交付前自查（必须回答，写进回报）

1. 冻结命中帧：能否一眼数出 N 道分叉 / N 个跳点？
2. 横截面：能否数出 3 档硬边（白芯 / 主体 / 外沿）？
3. 缩略图大小下，它是「一道电光 / 一条火束」，还是「一条白带子 / 一根管子」？
4. 有没有任何部件亮度 >1.0、或屏幕宽度 <6px？

## 6. 工程铁律

- 分段写：5~7 段，每段 ≤250 行，每段写完立刻 node --check；写入报错就把内容切小一半，不许重试同样写法。
- 纯函数：同一 t 同一画面；不许 Math.random / 读时钟；随机量走固定种子哈希。
- 参数全部外露（value/min/max/step/label）。

## 7. GLSL 真机雷区：11 条硬契约

> 2026-11-14 三轮实测 + 高星实践核验；本地静态检查、mock GL、GLSL 解析器全查不出，真机必炸。完整表与规避手法见 `glsl-guardrails.md`。

1. **VS/FS 成对共享的 uniform 必须显式写一致精度**：VS 默认 highp float/int，FS 默认 mediump——两边都省限定词，链接期报 `Precisions of uniform 'X' differ`。稳妥写法：共享 uniform 两边都写 `uniform highp ...`。
2. **fwidth / dFdx / dFdy 是片元专用**：出现在 VS 源码里（哪怕只是公共块里"定义了没调用"的函数）都会编译失败。带导数的公共函数只能拼进 FS。
3. **GLSL 保留字不能当标识符**：patch、sample、filter、common、buffer、shared、active、partition、subroutine、input、output、resource、coherent、restrict、readonly、writeonly、noperspective、half、fixed、unsigned、long、short、double、superp、packed 等。
4. **类型维度要盯死**：`vec2 hash21(float)` 返回 vec2，赋给 float 就是维度不匹配；ES 3.00 禁止 int→float 隐式转换。
5. **报错行号是拼接后的**：宿主打印的行号 = 公共块 + 你的源码；定位自己代码时要减去公共块行数。
6. attribute 建议写 `layout(location = N)`，防增删 in 时 JS 侧绑定静默错位。
7. **用了没声明的标识符**（`undeclared identifier`）本地扫描不可靠，以真机编译为准。
8. **禁止 `fract(sin(x) * 43758.5453)` 哈希**：sine hash 在不同 GPU 上图案本身就不一致，会直接破掉「同 t 同画面」的纯函数纪律。替代品**分两种宿主**：
   - **原生 GLSL ES 300 页面**：整数 PCG（`uint` + 位移乘法），跨驱动位级一致；
   - **只做文本替换的 WebGL1 兼容层（案例 A 的宿主）**：运行时只做四处文本替换、无原生 300 分支，`uint`/`layout`/`in-out` 都会编译失败 → 用**无 sin 的浮点哈希**：

```glsl
float hash11(float p){ p = fract(p*0.1031); p *= p+33.33; p *= p+p; return fract(p); }
float hash12(vec2 p){ vec3 p3 = fract(vec3(p.xyx)*0.1031); p3 += dot(p3, p3.yzx+33.33); return fract((p3.x+p3.y)*p3.z); }
```

   验收：同 t 两次截图像素 diff 必须 = 0。

9. **`max(fwidth(d), 0.0008)` 是逐字硬契约，且每个 shader 最多出现一次**：
   - 某些宿主的文本替换是 `String.replace(字面量, "0.0125")` —— **没有全局标志，只替换第一处**（同一函数里 attribute/varying 等四条都有全局标志，唯独这条没有）；
   - 后果：同一个 shader 里写两次，第二处会留在 WebGL1 上 → 整层编译失败；
   - 对策：把导数宽度收成**唯一入口**（如 `float vkAAWidth(/*d*/){ return max(fwidth(d), 0.0008); }`），其它地方都调它——这样全文件只有 1 处字面量；
   - 写法必须逐字符一致（空格、参数名都不能改），否则替换不命中。

10. **GLSL ES 100 的 for 循环上界必须是常量**：`for (int i=0; i<layers; i++)`（layers 是 uniform）在 WebGL1 不合法。兼容层宿主里 FBM 层数只能写死常量（改层数 = 构建期替换/重编译），只有在原生 300 页面里才用动态循环。

11. **反向 smoothstep（edge0 >= edge1）是规范未定义行为**：写成 `1.0 - smoothstep(lo, hi, x)` 等价形式，曲线一致且驱动无关。

## 8. 可观测性（强烈建议）

每个特效留 `uniform int uDebug;` 六档：0 成品 / 1 距离场 / 2 法线 / 3 部件 id / 4 步数·迭代 / 5 遮罩·alpha / 6 光照项。出问题时先拍 1/3/5 三张探针图定位，比对着成品猜快一个数量级。

另：`max(NaN, 0.0)` 在 GLSL 里返回 0.0，`step(d, NaN)` 恒为 1——NaN 会静默污染整条 min/step 记账链；用显式 `if (d < bestD)` 且入口守卫 `(d >= 0.0 && d < 1e8)`。
