## 0. 定位：**主观 → 客观的翻译器**（不是美化器，也不是技法注入器）

这个文件的职责只有一件事：**把用户嘴里的观感词，翻译成模型能执行、验收能量化的客观指标**（§3.5）。

判据很硬：**一份产出里没有「验收指标表」（每条指标 + 阈值 + 怎么量），就等于没翻译完**。这条是骨架第十节的由来。

**越界的两条警戒线**（两条都实锤踩过，不是假想）：

1. **不要替用户做风格决定**。给硬阶公式、强制加勾线、锚点全点二次元——这些都是替用户拍了「走哪种美术风格」的板。见 §0.2 的翻车反例。
2. **不要为了显得专业而编精确数字**。看起来精确的假指标比「暂无口径」更坏：它会让模型朝一个错的方向稳定优化（§3.5 末尾那条硬规矩）。

## 0.1 三条信条（违反必翻车，全是实测）

1. **观感语言 > 工程清单**。模块清单式需求让所有模型收敛到同一个安全解（管子/带子/白块）；大表合规（点名 30 个 uniform、自查四问、逐模块交表）会吃掉模型的「画面预算」，产出「模块全细节糙」。
2. **风格锚点要具体**。「3A 次世代二次元卡渲」这种口号检索不出任何视觉语法；「对标：崩坏：星穹铁道、绝区零，硬色阶、干净描边、动画感流动火焰」一句顶一段。
3. **卡渲 ≠ 把一切 posterize**。二次元感来自 形状语言、勾线、明暗大关系、发光感；cel band 是表面着色技法，不是特效技法。硬色阶是**可选风格化手段**，不是教义——「硬色阶量化」立成第一教义后，模型会把噪声/渐变/辉光全剁成档，剁出来的就是像素噪点渣、等高线晕圈、平涂糊条。

## 0.2 技法一律条件式（2026-11-15 翻车反例）

**反例原样记下来**：2026-11-15，用户的 12 份需求里**一次都没提卡渲**，但产出的 12 份施工版**全带卡通硬描边**，用户一眼看出偏差。

病根不在模型，在需求书：当时的文档里写着「描边与阴影边界统一用 `smoothstep(d-fw, d+fw, x)` 写法——这是成熟卡渲项目的通用做法」，于是每一份施工版都抄了一条「统一写法」，不管原文要不要卡渲。原文只说「加细暗红描边」（那完全可以是一圈柔和窄暗色过渡），下发的却是硬阶 + fwidth 抗锯齿。

同批还有两个同类：

- 「双重勾线单独成节，惊艳感的一半来自它」→ 所有需求都被强制加勾线，纯能量体/写实向根本不该有；
- 风格锚点只列二次元作品（星穹铁道/绝区零/原神）→ 系统性把一切往二次元卡渲拽。

**修正后的规矩**（本文件全篇照此执行）：

| 东西 | 什么时候给 | 什么时候不给 |
|---|---|---|
| 硬阶公式 `smoothstep(edge-fw*thick, edge+fw*thick, d)` | 原文明确要「卡通 / 赛璐璐 / 锐利轮廓 / 硬边」 | 原文只说「亮边 / 光边 / 窄暗描边」这类柔和意图 → 只写意图（发光过渡、暗色窄带），技法留给模型 |
| 双重勾线专节 | 用户或参考图里有明确「轮廓线、暗边、勾边」 | 只提到「发光边缘、光晕、能量外壳」→ 不写描边 |
| 二次元风格锚点 | 用户要的就是二次元 | 用户要写实/抽象/科幻 → 按他的取向点名对应作品 |

**一句话判据**：凡是「技法」，都必须挂在「原文是否要求该风格」这个条件下面；凡是「指标」，都必须能测量。

## 2. 风格锚点怎么写

- **点名作品，但别只点二次元**。锚点的作用是「检索到一套视觉语法」：
  - 二次元向 → 星穹铁道 / 绝区零 / 原神 / 鬼灭之刃；
  - 写实向 → 具体影视/游戏的特效镜头；
  - 抽象/科幻向 → 具体作品里的能量体设计。
  **注意**：三份需求的锚点全是二次元作品，模型就会系统性把一切往二次元卡渲拽（2026-11-15 实测过的偏差）。用户没要求二次元时，别自己加。
- 最多两三个锚点，附一句判词收束（「干净描边、动画感流动，不是写实影视火焰」）。
- **色彩写成逻辑链**：「亮芯白→明黄→橙→橘红→暗红」比「暖色系」强十倍；补一句「有限色阶量化是手段之一，允许平滑边界」防止剁档教义。
- **负面清单短而准**：「拒绝写实体积火焰与 PBR 连续渐变」一句即可，别列十条禁令。

## 3. 形态系统：自由度 + 正确性锚点（核心）

每个部件写三样东西：

1. **它是什么形状**（用观感语言）：「细长射线弹道」「短而硬的折线刺芒」「柔和慢滚的大雪团」；
2. **允许它怎么动**（自由度）：**只说「允许动到什么程度」，别指定动法**。例：「中心线允许小幅抖动/摆动，幅度 ≤5% 长度」「外缘允许被噪声撕裂」。锁死（「禁止弯曲/摇摆/扭变」）出来的是僵直激光；指定「必须正弦摇摆」又走到另一个极端。
3. **正确的样子**（正确性锚点，降方差的关键）：
   - 可数性：「冻结帧一眼能数出 N 道分叉、N 个跳点」；
   - 形状形容词：折线要「脆」不要「面条」，雪团要「蓬」不要「球」，光束要「实心柱」不要「空壳」；
   - 主次与留白：谁是主角、占多大画面、哪里要透气（不写这条的后果：满屏闹腾没主次）；
   - 节奏四拍：出生/持续/爆发/消散各长什么样、各占多长（**四个时间段的边界值必须首尾相接、单调不重叠**，见 §7）；
   - **端点断言**（可机械检查的四条）：t=0 不得有残留、末帧必须全部消散、任何通道峰值 ≤1.0、不得存在屏幕宽度 <6px 的独立部件。

> 这几条「正确性锚点」是降方差的关键：一次性交付式写法给高上限，但一次成型方差也高——把正确样子写死，模型才不会在自由度里跑飞。

## 3.5 主观词 → 客观指标（**本文件的核心职能**）

用户说的「脆」「蓬」「糊」「有主次」都是观感词，模型无法执行。**必须先翻译成可测量的量**，否则等于没说。

| 用户话术 | 客观指标 | 怎么量（可脚本化） |
|---|---|---|
| 有主次 / 不闹 | **主角占屏面积比**；主角与背景的亮度差 | alpha>0.5 像素的包围盒面积 ÷ 全屏；主角区 luma 中位数 − 背景 luma |
| 糊成一片 | **局部对比度**；色相分散度 | 8×8 分块的 luma 标准差中位数；色相直方图有效档数 |
| 脆 / 锐利 | **边缘梯度幅值中位数**；边缘过渡宽度（px） | Sobel 梯度；沿法线扫 alpha 25%→75% 的像素距离（越短越锐） |
| **对比 / 层次（比值类）** | **比值 + 绝对尺寸必须同时约束** | 只给比值会被「整体压暗/整体提亮」刷满。实测：脉络÷岩体 luma 比值 3.57「达标」，但脉络只有 **2px 宽**、屏幕上根本看不见；改成「比值 ≥3 **且** 脉络宽 ≥4px」才有效 |
| 蓬松 / 柔和 / 过渡要软 | **屏幕上的过渡带宽（px）**，且必须**由屏幕梯度反推**，不能用固定场值阈值 | 沿法线扫 alpha（或密度）从 25%→75% 的像素距离。⚠️ 实测：用固定场值差当带宽时，`smoothstep` 中段梯度太陡，**密度差 0.06 在一根火舌上只对应 0.7px** → 出来是 1px 硬线。正确写法：宽度 = `fwidth(场) × 目标像素数` |
| 实心柱 / 不是空壳 | **中心 alpha ÷ 边缘 alpha** 比 | 沿横截面取径向 alpha 剖面 |
| 层次清楚 | **径向可辨档数** | 沿横截面扫一条线，luma 过阈次数（相邻档需 ≥8 级差） |
| 密度 / 量 | **单位面积离散件数** | 连通域计数 ÷ 区域面积 |
| **多少（数量区间）** | **数量区间 + 尺寸范围**（**必须给上下限，不能只给下限**） | 连通域计数 + 包围盒宽高。⚠️ 实测 1：只写「密集」不写数量，同一模型两版给出 30 根 vs 5 根（6 倍差）。⚠️ 实测 2：只写「暗部 ≥50%」，模型做到 **91%**，把岩体做成褐色触手、**熔岩脉络反而看不见** —— 达标反而更丑。**写成「50%~70%」这种区间** |
| **色散强度** | **通道偏移的像素宽度 ≤ 该处线宽的 k 倍** | 边缘彩色带宽（px）÷ 主体线宽（px）。⚠️ 实测：只写「强 RGB 色散」会刷成彩虹肥皂泡；写成「≤0.5×线宽」才可控 |
| 有速度感 | **沿运动方向的拉长比** | 包围盒长宽比；拖尾方向与速度向量夹角 |
| 立体 / 不是薄片 | **垂直收窄率**；不同高度层的相位差 | 底/中/顶三处宽度比；三处采样同一特征的位置偏移 |
| 压抑 / 压迫感 | **暗部占比** + 主角亮度反差 | luma<0.2 的像素占比；主角区亮度 ÷ 画面平均亮度 |
| 高级 / 不脏 | **饱和度与色相纯度**；无灰褐像素占比 | HSV 饱和度直方图；土色相段（30°~60°）占比 |
| 饱满 / 丰厚 | **覆盖率**（alpha>0.5 占比）与**叠加层数** | 像素统计；同一像素被几个 pass 覆盖（调试通道数） |

**三条贯穿全表的口径**（第二轮的教训，比任何单行都重要）：

1. **比值类指标必须配一个绝对尺寸下限**——比值能被「把分子做细、把分母做暗」刷满，而 2px 宽的东西在屏幕上等于不存在。
2. **凡是"量多少"的，一律给区间不给单边**——只给下限会推开到极端（暗部 ≥50% → 做到 91% 反而毁掉主体）。
3. **凡是"过渡/边缘/柔和"的，一律换算到屏幕像素**——场值差不是像素，梯度陡的地方 0.06 只等于 0.7px。

**用法**：写需求书时，把用户的原话写在括号里，中间写指标、后面写阈值。例：「火光要有主次（主角占屏 ≤20%，主角亮度 ≥ 背景 2 倍）」。

**给不出的怎么办（硬规矩，不许破）**：宁可写「这条暂时没有量化口径，靠参考图对照」，也**不要编一个看似精确的假指标**。

理由是实测过的：我们曾把「色阶可数」当成审美的代理，模型于是朝「档数更多、边界更硬」稳定优化，**越修越平**——假指标不会让产出变精确，只会让它朝错误方向收敛得更整齐。所以第十节里允许出现「暂无口径」行，那比编数字诚实。

## 4. 着色逻辑：勾线要不要，看风格

- **勾线（条件式）**：⚠️ 与卡渲同一个坑——曾把「双重勾线」当成每份需求必写项（理由是「惊艳感的一半来自它」），但**纯能量体、写实向、柔光向都不该有描边**，强加就是替用户做风格决定。
  - 判断依据：用户/参考图里有明确「轮廓线、暗边、勾边」才写；只提到「发光边缘、光晕、能量外壳」就别写描边。
  - 要写时给三样：① 哪几类部件有边（主干有、细分支没有，避免糊成一团）② 边是暗是亮（暗描边 vs 亮镶边）③ 宽度怎么定（**屏幕像素，不是世界单位**）。
- **轮廓软硬按美术对标决定，绝不预设硬边**。原文只给柔和意图 → 写意图（发光过渡、暗色窄带）；原文明确要卡通/赛璐璐/锐利轮廓 → 才给硬阶 `smoothstep(edge - fw*thick, edge + fw*thick, d)`（fw 取 fwidth 半像素）；**不要在同一份需求书里既不说风格、又给硬阶公式**，那等于替模型做风格决定。
- **透明度分层**写「谁不透明、谁半透、谁低透」；**混合**写「内核加法发光、外层正常透明，加法峰值 ≤1.0」（无 tone mapping 的台上 >1.0 直接裁白）。
- **色阶若要写：写意图 + 可测目标，别写死参数**。原话可以是「色阶之间有明显分界但不要锯齿」；量化交给 §3.5（边缘过渡宽度 px、可辨档数）。给「2~4px」这种数字必须说明依据（半像素抗锯齿量级），否则就是替模型调参。

## 5. 反模式黑名单（见到就改）

| 反模式 | 后果 | 改法 |
|---|---|---|
| 模块清单式堆砌（八个模块全必做） | 摊大饼，每样一点每样不惊艳 | 主次分级，附属件标「可选」 |
| uniform 点名大表（27~31 项） | 合规吃掉画面预算 | 「所有变量暴露为 uniform」一句原则 |
| 自查四问当验收标准 | 指标替代审美，越修越平 | 审美锚定用户/参考图/作品名 |
| 「硬色阶量化」当第一教义 | 像素噪点、等高线晕、平涂糊条 | 色阶降为可选手段 |
| 锁死形态自由度 | 僵直激光、呆板几何 | 给弯曲/摇摆/湍流的参数位 |
| 「3A 次世代标准」式空口号 | 模型各自瞎猜 | 换具体作品锚点 |
| 输出交付物写满自查报告 | 报告比画好看 | 只交代码+注释+参数说明 |
| **把技法当指标**（硬阶公式/双重勾线/四层发光当成必写项） | 所有需求被套同一个皮肤，用户一眼看出偏差 | 技法只在原文明确要求该风格时才给 |
| **风格锚点单一化**（锚点全是二次元作品） | 系统性把一切往二次元卡渲拽 | 按用户实际取向点锚点，别默认二次元 |
| **给精确数字但没依据**（「过渡 2~4px」） | 等于替模型调参，数字来源不可查 | 要么给依据，要么只给可测目标 |
| **主观词直接下发**（「要有高级感/压迫感」不翻译） | 模型无法执行，各自瞎猜 | 过一遍 §3.5 转成面积比/亮度差/过渡宽度 |
| **验收指标表缺失** | 无法判定「做没做到」，只能靠嘴 | 骨架第十节必填；给不出的写「暂无口径」 |

## 6. 舞台物理护栏（放在需求书尾部，不喧宾夺主）

这几条是示例宿主评测台的物理现实，跟观感无关但踩了必挂：无 tone mapping/bloom（亮度 >1.0 裁白）；主体预乘 alpha、光才走加法；端点钉死世界坐标；纯函数（同 t 同画面，禁 Math.random/读时钟）。

### 6.1 像素尺子（2026-11-15 修正：旧说法「1 世界单位 ≈ 120~140px」是错的）

**公式**：

```
pxPerUnit(depth) = canvasH / (2 * depth * tan(fovY / 2))
```

`canvasH` 画布高（px）、`depth` 该点到相机沿视线的距离、`fovY` 垂直视场角。

- 老文档写的「1 世界单位 ≈ 120~140 px」**实测不成立**：本机位命中点约 **92 px/单位**（720p 下），比旧说法大了 30~50% 的偏差——按它算线宽会一路偏粗。
- 更坑的是**贴地部件**：它沿视线径向被压缩到 **13~38 px/米**，因为相机俯角只有约 **13°**，地面几乎"侧对"视线。换算：`径向有效 px/米 ≈ pxPerUnit × sin(俯角)`，即约 **0.225 倍**；反推回去，13~38 px/米 对应地面各处的 **58~170 px/单位**——所以同一块地面，近处和远处的"1 单位"根本不是同一个像素数，必须逐处算。

**表 1：实测锚点（720p）**

| 量 | 值 | 说明 |
|---|---|---|
| 命中点（贴脸处）px/单位 | **≈92**（实测） | 旧文档「120~140」作废 |
| 相机俯角 | **≈13°** | 决定地面压缩系数 |
| 地面径向压缩系数 | **sin(13°) ≈ 0.225** | 沿视线方向的长度几乎被压掉 3/4 |
| 贴地部件有效 px/米（径向） | **13~38**（实测区间） | 反推地面各处 ≈58~170 px/单位 |
| 「看不见」阈值 | `< 6px` 屏宽 | 独立部件；同一部件的透视收细不算 |

**表 2：按 1/depth 的比例换算（同机位，以命中点 92 为锚）**

| 深度 | px/单位 | 1 世界单位占 1280 屏宽 | 6px 阈值 ≈ 多少世界单位 |
|---|---|---|---|
| 0.5× 命中点 | 184 | 14.4% | 0.033 |
| 1× 命中点 | **92** | 7.2% | 0.065 |
| 2× | 46 | 3.6% | 0.13 |
| 4× | 23 | 1.8% | 0.26 |

> 用法：先按公式算你机位、你距离上的 `pxPerUnit`，再判「这个部件在屏上是几 px」。**贴地线宽要按径向压缩后的像素算**，直接用命中点的 92 会高估三倍以上。

完整施工契约见 `construction-contracts.md`；GLSL 十一条硬契约与三条实现铁律见 `glsl-guardrails.md`。

**无 bloom 时的发光感必须自己造**（开源世界的发光都靠后处理，那套在这类舞台上整段作废）。但写需求书时**给目标不给公式**：要的是「亮部有向外溢出的层次感、且不被裁白」——具体是四层构造还是别的做法，让模型自己选（`no-bloom.md` 里那套四层构造只是**一个可选实现**，不是标准答案）。唯一硬约束：亮度峰值 ≤1.0、主体预乘、光才走加法。

**强烈建议每个特效留 `uDebug` 六档**（0 成品 / 1 距离场 / 2 法线 / 3 部件 id / 4 步数 / 5 遮罩 / 6 光照项）：出问题时先拍三张探针图，比对着成品猜快一个数量级。

## 7. 需求书自检（发出去之前过一遍）

施工方回传的高频问题不是「不会画」，而是**需求书内部不自洽**。这一节是发单前的机械自检，**十问**（前七问是两轮施工实报，后三问来自第二轮的返工）：

1. **时间轴是否单调一致**：节奏表里写了「0~0.3」，就不能又在别处写「≈0.35 峰值」。
   *实拍*：表格写「0.2~0.4 分支陆续劈落」、锚点又要求「0.25 峰值帧数出 ≥8 条」——按 0.25 均匀只接得上 2.7 条。**峰值时刻必须落在「全部件就位」之后**。
2. **形态数量前后是否一致**：「球形扩张冲击波」和「1 道激波环」是两种东西，只能留一个；「环形阵列」与锚点「不许均匀环形阵列」也不能并存。
3. **两套实现是否互斥**：「fract 时间回卷」与「速度场符号翻转」不能同时要求。
4. **枚举是否齐全**：写了「混合顺序表」就不能漏层（有几层就列几层，实测最常漏暗能丝、暗雾）。
5. **预算与结构是否冲突**：「draw call ≤4」和「6 段混合顺序」冲突时**必须给出解法**（撞怎么办），不能只并列。
6. **指代是否明确**：「1.8R 指谁」「垂直方向采样指什么」「≥8 片是整画面还是每圈」——凡是缩写、方位词、数量，都要能指着某一句话说清。
7. **规则之间是否互斥**：「禁止片元做边缘检测」与「用 SDF 解析带画边」若是同一份需求里的两条，要写明哪条优先（或哪类部件例外）。
8. **时间轴 vs 端点断言**：「t=0 无残留」与「0~0.2 是蓄力阶段」直接打架（蓄力阶段就已经有东西了）。
   *修法*：端点断言改成可判定的形态（如「t=0 时**不可见**」），或把蓄力整体前移到 t<0。
9. **可数性口径**：「≥18 枚冰锥」没说是峰值帧还是任意帧、没说多小算一枚。
   *修法*：写「**峰值帧** + 单个 **≥M px** + 判据（连通域 / 包围盒）」。
10. **做不到的公式**：要求「邻域采样 bloom」「背景 UV 扭曲」「`pow(1-dot(V,N),k)` 菲涅尔」这类无后处理管线做不到的写法。
    *修法*：换成等效的**可观测目标**（亮度峰值 ≤1.0、亮部向外溢出的层次感），实现让模型自选；见 `no-bloom.md` 与 `glsl-guardrails.md`。

**一句话**：需求书里每一个「数量 / 距离 / 时刻 / 档数」都要能回答——**在哪个范围、以什么为基准、怎么算出来的**。

过不了这十条的需求书不要发——模型会各挑一半执行，产出看着合规、实际自相矛盾。

## 8. 派单与验收流程（配合需求书使用）

1. **一次性交付**：一个模型一次跑完，不带自查报告负担——高上限来自完整创作权；
2. **真机快检是唯一可靠验收**：mock GL、静态扫描、GLSL 解析器都会漏（实测：未声明标识符、NaN 毒化、遮罩断链全漏过）；
3. **bug 返修轮只修落地不修设计**：改完必须前后 diff 同帧有可见差异才算修好；
4. **别让别的模型润色观感**（串行三级实验 18 棒的终审：润色是负功）；修 bug 可以跨模型，观感留给原作者或用户；
5. **每棒存快照**：用户终审后随时回滚最佳版本；
6. **审美终审权在用户**：判词也会失真，别拿自查指标当审美。

## 9. 用法

1. 跟用户聊出「想要的感觉」（关键词：像什么、什么气质、什么动作、什么颜色）；
2. 有参考图/视频就抓它的 形状/明暗/节奏 三条特征写进正确性锚点；
3. 把每一句观感词过一遍 §3.5，翻成指标（翻不出的写「暂无口径」）；
4. 按 §10 填空成稿，第十节把指标 + 阈值 + 怎么量列成表；
5. 过一遍 §7 自检与 `pitfalls.md`；
6. 派单、真机快检、bug 返修、用户终审。

## 11. 案例：F2 提示词为什么赢（以及它为什么不是万灵药）

> F2（2026-11-06，一次性跑出高上限火焰射线）的原始提示词 vs 后来九份需求书，六点差异。

1. **风格锚点**：F2「风格目标对标：星穹铁道、绝区零 二次元卡通火焰射线，硬色阶、干净描边、动画感流动火焰，不是写实影视火焰」；反例「目标是 3A 次世代标准二次元卡通卡渲风格……对标次世代二次元动作游戏」——检索不出任何东西。
2. **勾线**：F2 有专节「双重轮廓方案：①射线外边缘细黑/暗橘卡通描边（屏幕空间恒宽）②内核亮边高光勾边……fwidth 做屏幕空间宽度矫正」；反例九份需求书零勾线要求，只剩色块，怎么修都是糊。**但注意**：这是「这一支要卡通」所以给了勾线，不是「每支都要勾线」——条件式的边界见 §0.2。
3. **形态自由度**：F2「支持沿路径的曲率弯曲、正弦摇摆、湍流扭变」——轮廓有生命感；反例「禁止中心线弯曲、摇摆、扭变、蛇形偏移」——锁出僵直激光。
4. **轻合规**：F2「所有变量暴露为 uniform：射线起点终点、长度、锥度、毛刺强度……」一句话原则；反例「包括但不限于 u_time、u_globalAge……」27~31 项点名大表 + 自查四问 + 逐模块交表。
5. **可选项真可选**：F2「可选附加子效果（同 Shader 内参数开关，按需开启）：尾部火星 / 热力畸变（有屏幕 RT 才开，无 RT 可关闭）/ Bloom 引导」；反例八模块全必做，摊大饼。
6. **色阶措辞**：F2「硬色阶分层，平滑边界但支持轮廓描边」——干净的卡通色块；反例「色阶过渡使用可控硬过渡阈值，1 像素级软抗锯齿过渡」+「过渡宽度 fwidth 级（2~4px）」——720p 下就是像素噪点渣。

**但 F2 写法不是万灵药**：同写法 A/B 实验里，暴风雪一眼唬住人（上限极高）；闪电链白卡片翻车（方差也极高，落地 bug：NaN 毒化 min 记账链、遮罩没乘 alpha）。**结论：F2 写法给高上限，降方差靠「正确性锚点」+ 真机快检 + 只修落地的 bug 轮。**
