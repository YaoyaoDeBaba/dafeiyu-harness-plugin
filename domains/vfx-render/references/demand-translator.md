# VFX 需求翻译器：把「想要的感觉」写成可施工的需求书

> 来源：案例 A 的 vfx-req-translator 技能（`SKILL.md` + `references/template.md` + `references/examples.md`），2026-11-14 随案例移交
> 许可：自研（随案例移交；未单独声明开源许可证）
> 适用宿主：案例 A 的 WebGL 视觉宿主（原生 GLSL ES 300 页面，或只做文本替换的 WebGL1 兼容层）
> 吸收说明：三份合并为一份；去掉 skill front-matter、来源方内部复盘指路与仓库内路径；交付物一节改成「按宿主契约」表述，其余保留九节骨架、三条信条、形态自由度/正确性锚点与 F2 案例。

> 输入：一句「我想要个 XX 技能的感觉」、一段参考图/视频、或一份旧需求书。
> 输出：一份可直接派单的施工需求书。**写「画成什么样」，不写「造什么东西、交什么表」。**
> 方法论来自 2026-11-14 的三实验复盘（独立竞标 / 串行修改 / 提示词变量）。

## 0. 三条信条（违反必翻车，全是实测）

1. **观感语言 > 工程清单**。模块清单式需求让所有模型收敛到同一个安全解（管子/带子/白块）；大表合规（点名 30 个 uniform、自查四问、逐模块交表）会吃掉模型的「画面预算」，产出「模块全细节糙」。
2. **风格锚点要具体**。「3A 次世代二次元卡渲」这种口号检索不出任何视觉语法；「对标：崩坏：星穹铁道、绝区零，硬色阶、干净描边、动画感流动火焰」一句顶一段。
3. **卡渲 ≠ 把一切 posterize**。二次元感来自 形状语言、勾线、明暗大关系、发光感；cel band 是表面着色技法，不是特效技法。硬色阶是**可选风格化手段**，不是教义——「硬色阶量化」立成第一教义后，模型会把噪声/渐变/辉光全剁成档，剁出来的就是像素噪点渣、等高线晕圈、平涂糊条。

## 1. 需求书骨架（九节）

| 节 | 写什么 | 写法要点 |
|---|---|---|
| 开发约束 | 纯 WebGL2 / 零外部资源 / GLSL ES 300 手写 | 一两句带过，别展开成工程规范 |
| 渲染风格 | 风格锚点 + 色彩逻辑链 + 负面清单 | 见 §2 |
| 形态系统 | 每个部件的 形态自由度 + 正确性锚点 | 见 §3，全书最重的一节 |
| 着色逻辑 | 双重勾线专节 / 透明度分层 / 发光与混合 | 见 §4 |
| 品质细节 | 分层扰动、节奏、闪烁 | 低/中/高频各管什么 + 各自流速相位 |
| 性能预算 | 给档位不给枷锁 | 「FBM ≤6 层、可降 3」式一句话即可 |
| 可选项 | 标明「可选、按需、可关」 | 真可选；别把八模块全写成必做 |
| 输出交付物 | 契约一段 + 注释要求 | 轻！uniform 只给原则，不点名大表 |
| 风格对标 | 具体游戏名 + 一句视觉判词 | 收尾点题，和 §2 呼应 |

## 2. 风格锚点怎么写

- **点名游戏**：崩坏：星穹铁道 / 绝区零 / 原神 / 鬼灭之刃这类有明确视觉语法的作品；最多两三个，附一句判词收束（「干净描边、动画感流动，不是写实影视火焰」）。
- **色彩写成逻辑链**：「亮芯白→明黄→橙→橘红→暗红」比「暖色系」强十倍；补一句「有限色阶量化是手段之一，允许平滑边界」防止剁档教义。
- **负面清单短而准**：「拒绝写实体积火焰与 PBR 连续渐变」一句即可，别列十条禁令。

## 3. 形态系统：自由度 + 正确性锚点（核心）

每个部件写三样东西：

1. **它是什么形状**（用观感语言）：「细长射线弹道」「短而硬的折线刺芒」「柔和慢滚的大雪团」；
2. **允许它怎么动**（自由度）：曲率弯曲、正弦摇摆、湍流扭变、锥度、膨胀收缩——给模型留出「画活」的空间。锁死（「禁止弯曲/摇摆/扭变」）出来的东西就是僵直激光；
3. **正确的样子**（正确性锚点，降方差的关键）：
   - 可数性：「冻结帧一眼能数出 N 道分叉、N 个跳点」；
   - 形状形容词：折线要「脆」不要「面条」，雪团要「蓬」不要「球」，光束要「实心柱」不要「空壳」；
   - 主次与留白：谁是主角、占多大画面、哪里要透气（不写这条的后果：满屏闹腾没主次）；
   - 节奏四拍：出生/持续/爆发/消散各长什么样、各占多长；
   - **端点断言**（可机械检查的四条）：t=0 不得有残留、末帧必须全部消散、任何通道峰值 ≤1.0、不得存在屏幕宽度 <6px 的独立部件。

> 这几条「正确性锚点」是降方差的关键：F2 式写法给高上限，但一次成型方差也高——把正确样子写死，模型才不会在自由度里跑飞。

## 4. 着色逻辑：勾线是灵魂

- **双重勾线单独成节**：①外缘细描边（暗色 toon 描边，屏幕空间恒宽、fwidth 校正）②内核亮边高光勾边（宽度独立可控）。惊艳感的一半来自它；九份反例需求书全漏了它。
- **描边与阴影边界统一用 `smoothstep(d-fw, d+fw, x)` 写法**（d 是阈值、fw 由 fwidth 给的半像素宽）——这是 URP_Toon 等成熟卡渲项目的通用做法：两档硬阴影 + rim 三开关 + 独立描边 pass，全是参数不靠贴图。
- **透明度分层**写「谁不透明、谁半透、谁低透」；混合写「内核加法发光、外层正常透明，加法峰值 ≤1.0」（评测台无 tone mapping，>1.0 直接裁白）。
- 色阶若要写：写「档内纯色、过渡 2~4px、可开关软抗锯齿」，别写「严格 fwidth 硬过渡」——720p 下就是噪点渣。

## 5. 反模式黑名单（见到就改）

| 反模式 | 后果 | 改法 |
|---|---|---|
| 模块清单式堆砌（八个模块全必做） | 摊大饼，每样一点每样不惊艳 | 主次分级，附属件标「可选」 |
| uniform 点名大表（27~31 项） | 合规吃掉画面预算 | 「所有变量暴露为 uniform」一句原则 |
| 自查四问当验收标准 | 指标替代审美，越修越平 | 审美锚定用户/参考图/游戏名 |
| 「硬色阶量化」当第一教义 | 像素噪点、等高线晕、平涂糊条 | 色阶降为可选手段 |
| 锁死形态自由度 | 僵直激光、呆板几何 | 给弯曲/摇摆/湍流的参数位 |
| 「3A 次世代标准」式空口号 | 模型各自瞎猜 | 换具体游戏锚点 |
| 输出交付物写满自查报告 | 报告比画好看 | 只交代码+注释+参数说明 |

## 6. 舞台物理护栏（放在需求书尾部，不喧宾夺主）

这几条是示例宿主评测台的物理现实，跟观感无关但踩了必挂：无 tone mapping/bloom（亮度 >1.0 裁白）；主体预乘 alpha、光才走加法；720p 下部件 <6px 等于看不见（1 世界单位 ≈ 120~140px）；端点钉死世界坐标；纯函数（同 t 同画面，禁 Math.random/读时钟）。

完整施工契约见 `construction-contracts.md`；GLSL 八雷与可观测性见 `glsl-guardrails.md`。

**无 bloom 时的发光感必须自己造**（开源世界的发光都靠后处理，那套在这类舞台上整段作废）：内核实心 → 3~5 档硬色阶外扩 → 外缘加法晕 → 极轻抖动消 banding。写法与公式见 `no-bloom.md`，写进需求书别留给模型猜。

**强烈建议每个特效留 `uDebug` 六档**（0 成品 / 1 距离场 / 2 法线 / 3 部件 id / 4 步数 / 5 遮罩 / 6 光照项）：出问题时先拍三张探针图，比对着成品猜快一个数量级。

## 7. 派单与验收流程（配合需求书使用）

1. **一次性交付**：一个模型一次跑完，不带自查报告负担——高上限来自完整创作权；
2. **真机快检是唯一可靠验收**：mock GL、静态扫描、GLSL 解析器都会漏（实测：未声明标识符、NaN 毒化、遮罩断链全漏过）；
3. **bug 返修轮只修落地不修设计**：改完必须前后 diff 同帧有可见差异才算修好；
4. **别让别的模型润色观感**（串行三级实验 18 棒的终审：润色是负功）；修 bug 可以跨模型，观感留给原作者或用户；
5. **每棒存快照**：用户终审后随时回滚最佳版本；
6. **审美终审权在用户**：主号判词也会失真，别拿自查指标当审美。

## 8. 用法

1. 跟用户聊出「想要的感觉」（关键词：像什么、什么气质、什么动作、什么颜色）；
2. 有参考图/视频就抓它的 形状/明暗/节奏 三条特征写进正确性锚点；
3. 按下面的填空模板成稿；
4. 对照 `pitfalls.md` 过一遍反模式；
5. 派单、真机快检、bug 返修、用户终审。

## 10. 案例：F2 提示词为什么赢（以及它为什么不是万灵药）

> F2（2026-11-06，一次性跑出高上限火焰射线）的原始提示词 vs 后来九份需求书，六点差异。

1. **风格锚点**：F2「风格目标对标：崩坏：星穹铁道、绝区零 二次元卡通火焰射线，硬色阶、干净描边、动画感流动火焰，不是写实影视火焰」；反例「目标是 3A 次世代标准二次元卡通卡渲风格……对标次世代二次元动作游戏」——检索不出任何东西。
2. **双重勾线**：F2 有专节「二次元轮廓勾线：双重轮廓方案：①射线外边缘细黑/暗橘卡通描边（屏幕空间恒宽）②内核亮边高光勾边……fwidth 做屏幕空间宽度矫正」；反例九份需求书零勾线要求。没有勾线只剩色块，怎么修都是糊。
3. **形态自由度**：F2「支持沿路径的曲率弯曲、正弦摇摆、湍流扭变」——轮廓有生命感；反例「禁止中心线弯曲、摇摆、扭变、蛇形偏移」——锁出僵直激光。
4. **轻合规**：F2「所有变量暴露为 uniform：射线起点终点、长度、锥度、毛刺强度……」一句话原则；反例「包括但不限于 u_time、u_globalAge……」27~31 项点名大表 + 自查四问 + 逐模块交表。
5. **可选项真可选**：F2「可选附加子效果（同 Shader 内参数开关，按需开启）：尾部火星 / 热力畸变（有屏幕 RT 才开，无 RT 可关闭）/ Bloom 引导」；反例八模块全必做，摊大饼。
6. **色阶措辞**：F2「硬色阶分层，平滑边界但支持轮廓描边」——干净的卡通色块；反例「色阶过渡使用可控硬过渡阈值，1 像素级软抗锯齿过渡」+「过渡宽度 fwidth 级（2~4px）」——720p 下就是像素噪点渣。

**但 F2 写法不是万灵药**：同写法 A/B 实验里，暴风雪一眼唬住人（上限极高）；闪电链白卡片翻车（方差也极高，落地 bug：NaN 毒化 min 记账链、遮罩没乘 alpha）。**结论：F2 写法给高上限，降方差靠「正确性锚点」+ 真机快检 + 只修落地的 bug 轮。**
