> 许可：自研（随案例移交；未单独声明开源许可证）
> 适用宿主：案例 A 的 WebGL 视觉宿主（原生 GLSL ES 300 页面或只做文本替换的 WebGL1 兼容层）
> 吸收说明：原表逐字保留；新增 §二 的七行来自 2026-11-15 施工侧回传（原来 skill 完全没覆盖，属最大缺口），只吸收"症状 → 需求书写法修正"这一层，不搬施工方内部实现。**本版基于 2026-11-15 实跑修订。**

## 一、成品翻车：症状 → 写法修正

| 翻车症状（真机实拍） | 病根 | 需求书写法修正 |
|---|---|---|
| 像素噪点渣撒满主体周围 | hash × step 硬阈值当碎闪 | 碎闪写「只影响亮度与边缘、少量点缀」，禁 floor 格子化 |
| 紫晕等高线圈 / 平涂糊条 | 「硬色阶量化」当教义 | 色阶降为可选手段，写「平滑边界+勾线」 |
| 白色大卡片/矩形裸奔 | SDF 遮罩没乘 alpha、quad 没盖住可见区 | 正确性锚点写「任意 t 下 quad 边界不可见」 |
| 只见大白球、主体没做出来 | 白核占比失控、主体空壳 | 主次锚点写「白芯占比小、主体是 X 屏宽的实心柱」 |
| 灰石头/发灰发脏 | 明度通路与色卡错位、暗档占比过大 | 色彩锚点写「最亮档是主角、暗档只做描边/阴影」 |
| 僵直激光、呆板 | 形态自由度被锁死 | 给弯曲/摇摆/湍流参数位（只说"允许动到什么程度"） |
| 满屏闹腾没主次 | 没写主次与留白 | 正确性锚点必含「主次占比、哪里透气」 |
| 模块全细节糙 | 合规负担吃掉画面预算 | uniform 一句话原则、自查报告不进交付物 |
| 越修越平、跨模型润色毁观感 | 指标替代审美 | 不让别的模型碰观感；修 bug 只修落地 |
| 贴地物 z-fighting / 撑破 quad | 几何没盖住内容 | 护栏写「多边形偏移 + 内容半径 < quad 半宽」 |
| **12 份需求全被套上卡通硬描边**（2026-11-15） | 需求书里写死了"统一硬阶写法"，把技法当指标 | 技法条件式：原文要卡通/赛璐璐才给硬阶；只给柔和意图就只写意图 |
| **成品全往二次元卡渲拽** | 风格锚点只列二次元作品 | 按用户实际取向点锚点；写实/抽象向各点各的 |

## 二、需求书内部不自洽（2026-11-15 施工侧回传的高频问题）

施工方报上来的问题里，最大一类不是"不会画"，而是**需求书自己打架**——模型只好各挑一半执行。这七行都是"发单前三十秒能查出来"的，本包建议照 §3 的轻重取舍使用。

| 症状（施工方原话） | 类型 | 需求书写法修正 | 建议 |
|---|---|---|---|
| 节奏表写「0~0.3」又写「≈0.35 峰值」 | 时间轴自相矛盾 | 四拍边界必须首尾相接、单调不重叠；峰值时刻落在某一拍内部并写明 | **必进坑表**：最常犯、最好查 |
| 「球形扩张冲击波」vs「1 道激波环」 | 形态数量不一致 | 形态只留一种；若两种都要，写明主次与各自占比 | **必进坑表**：直接决定成品的可数性锚点 |
| 「fract 时间回卷」与「速度场符号翻转」互斥 | 两套实现冲突 | 二选一；要混用必须写清谁在哪一段生效 | 进坑表：属"实现路线"层，选错就是全盘重做 |
| 混合顺序表漏了某些层 | 枚举不全 | 层数 ≤ 结构层数，且每一层在表里出现一次 | 进坑表：改法机械，最好机械检查 |
| 「draw call ≤4」与「6 段混合顺序」冲突且没给解法 | 预算与结构冲突 | 撞预算时必须给解法（哪些段合批/哪些降级），不能只并列 | 进坑表：并列本身就是错 |
| 「1.8R 指谁」「垂直方向采样指什么」 | 指代不明 | 缩写与方位词都要能指回唯一一句；尺寸以技能 L/R 为单位给 | 进坑表：成本最低、收益最高 |
| 「禁止片元做边缘检测」vs「用 SDF 解析带画边」 | 规则互斥 | 写明哪条优先，或哪类部件例外（如 impostor 部件） | 部分保留：例外条款属施工约束，写法上写"优先级 + 例外名单"即可 |

> 判据一句话：**发单前把需求书当代码读一遍，凡是两句话能推出矛盾的，都是需求书的锅，不是模型的锅。** 具体七问的清单位于 `demand-translator.md` §7。
