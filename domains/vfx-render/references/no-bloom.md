# 无后处理的发光感怎么做（**可选参考**，不是必做）

> 来源：案例 A 的 vfx-req-translator 技能 `references/no-bloom.md`，2026-11-14 随案例移交；2026-11-15 按修订版改成"可选实现之一"并修正像素尺子
> 许可：自研（随案例移交；未单独声明开源许可证）
> 适用宿主：没有 tone mapping、bloom 与后处理抗锯齿的 WebGL 评测台（案例 A 的舞台）
> 吸收说明：原文搬入；补这段统一元信息，把「评测台」明确为案例 A 的示例宿主舞台，按 2026-11-15 修订版**把四层构造降级为可选实现**（需求书写"给目标不给公式"），并把「1 世界单位 ≈ 120~140px」按实测改成公式 + 表。**本版基于 2026-11-15 实跑修订。**

> ⚠️ **定位先说清：这是可选参考，不是标准答案。**
> 舞台事实：评测台没有 tone mapping、没有 bloom、没有后处理抗锯齿；开源世界的发光感几乎都靠后处理（Bloom 库、AgX 曲线、dither 链），那套在这类舞台上整段作废。
> 但**写需求书时不要把这套四层构造写成必做**——要的是「亮部有向外溢出的层次感、且不被裁白」这个**目标**，具体几层、怎么叠，留给模型选。把这里的构造当公式下发，就是替模型做了实现决定（与 `demand-translator.md` §0.2 同一类错）。
> 唯一硬约束三条：亮度峰值 ≤1.0、主体预乘、光才走加法。

## 一、四层构造法（**一个**可选实现）

| 层 | 做法 | 视觉作用 |
|---|---|---|
| ① 内核实心 | 纯白或近白不透明核心，加法或预乘，面积占比小（约 10~20%） | 亮度锚点，烧的感觉 |
| ② 色阶外扩 | 3~5 档硬色阶向外递减（白→黄→橙→橘红→暗红），档内纯色 | 卡通层次，替代 bloom 的渐晕 |
| ③ 外缘加法晕 | 半径外沿一圈低 alpha 加法（峰值 ≤0.5） | 让边缘溢出到背景，模拟辉光 |
| ④ 抖动消 banding | 极少量蓝噪声抖动（±1/255 级） | 8bit 输出在无后处理时必然出现色带，这是唯一零成本补救 |

> 不选这套也行：只要满足三条硬约束、且"亮部有由内向外的层次降序"，峰值不超过 1.0 的其它构造同样合格。

## 二、关键原则（这几条是硬约束，不是可选）

1. 亮度峰值必须 ≤1.0：超过就被裁成纯白，层次全丢（真机上真正踩到的坑——白球会把五档金阶全吃掉）。
2. 层次靠色值不靠亮度：(1.0, 0.8, 0.3) 比 (2.0, 1.6, 0.6) 好看，后者会被裁成白色。
3. 加法只给光，不给主体：主体（色块、描边、贴地面）走预乘，加法会把 RGB 三通道一起推满烧成纯白。
4. 绘制顺序（若你采用这类叠层做法）：外晕(加法) → 外沿(预乘) → 主体(预乘) → 白芯(加法) → 火花/闪光(加法)。

## 三、部件的最小可读尺寸（像素尺子已修正）

720p 下部件屏幕宽度 < 6px 基本看不见。**旧说法「1 世界单位 ≈ 120~140 px」是错的**——本机位实测命中点约 **92 px/单位**；贴地部件沿视线径向还被压到 **13~38 px/米**（相机俯角仅约 13°，径向压缩系数 ≈ sin(13°) ≈ 0.225）。

所以判"看不看得见"要分两步：

| 部件类型 | 用哪个数 | 720p 下 6px 门槛 ≈ |
|---|---|---|
| 竖着对镜头的（火花、白芯、外晕） | 命中点 **92 px/单位** | ≈0.065 世界单位 |
| 贴地铺开的（焦痕、霜斑、地面轨迹） | 径向 **13~38 px/米** | ≈0.16~0.46 单位 |

公式与完整两张表见 `demand-translator.md` §6.1。所有发光颗粒、描边带、色阶细带都要过这个门槛——远端的自然收细可以接受（同一部件的透视），但独立部件不行。

## 四、抖动实现（蓝噪声近似，无贴图）

```glsl
// 无贴图蓝噪声近似：PCG 哈希在像素坐标上做三角分布抖动
float dither(vec2 fc, float level){
    float n = hash12(fc) + hash12(fc + 17.13) - 1.0;   // 三角分布 [-1,1]
    return n * level;   // level ≈ 1.0/255.0 量级
}
```
只在最后输出前加，且幅度要小到缩略图看不出来。
