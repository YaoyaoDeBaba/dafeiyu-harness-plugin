> 开源世界的发光感几乎都靠后处理（Bloom 库、AgX 曲线、dither 链），那套在这类舞台上整段作废。

## 一、四层构造法

| 层 | 做法 | 视觉作用 |
|---|---|---|
| ① 内核实心 | 纯白或近白不透明核心，加法或预乘，面积占比小（约 10~20%） | 亮度锚点，烧的感觉 |
| ② 色阶外扩 | 3~5 档硬色阶向外递减（白→黄→橙→橘红→暗红），档内纯色 | 卡通层次，替代 bloom 的渐晕 |
| ③ 外缘加法晕 | 半径外沿一圈低 alpha 加法（峰值 ≤0.5） | 让边缘溢出到背景，模拟辉光 |
| ④ 抖动消 banding | 极少量蓝噪声抖动（±1/255 级） | 8bit 输出在无后处理时必然出现色带，这是唯一零成本补救 |

## 二、关键原则

1. 亮度峰值必须 ≤1.0：超过就被裁成纯白，层次全丢（真机上真正踩到的坑——白球会把五档金阶全吃掉）。
2. 层次靠色值不靠亮度：(1.0, 0.8, 0.3) 比 (2.0, 1.6, 0.6) 好看，后者会被裁成白色。
3. 加法只给光，不给主体：主体（色块、描边、贴地面）走预乘，加法会把 RGB 三通道一起推满烧成纯白。
4. 绘制顺序：外晕(加法) → 外沿(预乘) → 主体(预乘) → 白芯(加法) → 火花/闪光(加法)。

## 三、部件的最小可读尺寸

720p 下部件屏幕宽度 < 6px 基本看不见（1 世界单位 ≈ 120~140 px）。所有发光颗粒、描边带、色阶细带都要过这个门槛——远端的自然收细可以接受（同一部件的透视），但独立部件不行。

## 四、抖动实现（蓝噪声近似，无贴图）

```glsl
// 无贴图蓝噪声近似：PCG 哈希在像素坐标上做三角分布抖动
float dither(vec2 fc, float level){
    float n = hash12(fc) + hash12(fc + 17.13) - 1.0;   // 三角分布 [-1,1]
    return n * level;   // level ≈ 1.0/255.0 量级
}
```
只在最后输出前加，且幅度要小到缩略图看不出来。
